## 1. 怎么查空闲节点

```bash
jcc node list                                  # 全部节点；最后一列 GPU 形如 0/8（全空）/ 3/8 / 8/8（满）
jcc node list | awk '$5=="0/8"'                # 只看整节点空闲的（多机训练要整节点）
jcc node list | awk '$5=="0/8"' | wc -l        # 空闲整节点数量
```
- 一个节点 = 8×H100 80G、~95.7 CPU、~1977Gi RAM。
- 多机训练（gpuPerWorker=8）**每 worker 占一整节点**，所以要 N 节点就得有 N 个 `0/8` 节点。
- `>8 卡`（多机）按集群指南需先找 Tom 要额度；但实测此前 4×8 探针/训练能直接调度起跑（见下）。

## 3. 4×8（=32卡/4节点）跨节点 rendezvous 配方 ✅ 已实测可用

**背景**：jcc **不注入** torch 的多机 rendezvous env（没有 MASTER_ADDR/RANK/WORLD_SIZE，只有 k8s service env）。
要自己用 **pod DNS** 组 rendezvous。下面是实测成功的写法（smoke `evan-mot-train256-4x8-smoke-4tjc` 跑通 32-rank NCCL）。

```bash
HOST=$(hostname)                                          # 实测 = <jobname>-<rank>，例: evan-mot-xxx-0（无随机后缀！）
NODE_RANK=${HOST##*-}                                     # 末段 dash 后 = node rank（0..N-1）
JOB_BASE=${HOST%-${NODE_RANK}}
MASTER_ADDR=${JOB_BASE}-0.jobs.default.svc.cluster.local  # node-0 的 pod DNS（headless service）
MASTER_PORT=29571

# 等 master DNS 起来（节点冷启动有先后，必须等！）
for i in $(seq 1 180); do getent hosts "$MASTER_ADDR" && break; sleep 2; done
getent hosts "$MASTER_ADDR" || { echo "master dns 解析失败"; exit 20; }

python -m torch.distributed.run \
  --nnodes=4 --nproc_per_node=8 --node_rank=$NODE_RANK \
  --master_addr=$MASTER_ADDR --master_port=$MASTER_PORT \
  train.py --config ... 
```

**坑 / 实测要点**：
- ⚠️ `hostname` 返回 `<jobname>-<rank>`，**没有随机后缀**（jcc log 前缀里的 `-<5位随机>` 是 pod 名，不是 hostname）。
  - 所以 rank 提取用 `${HOST##*-}`。**别用** `sed 's/.*-([0-9]+)-[^-]+$/\1/'`（假设有后缀，本集群会失配 → 全 worker 挂）。
- IB 不可用 → NCCL 自动回退 **Socket/TCP**（日志 `Failed to initialize NET plugin IB` → `Initialized NET plugin Socket`，正常）。
  - 32-rank `ncclCommInitRank` bootstrap ~84s；256px 小模型每步数秒级（Socket 通信是瓶颈，分辨率越低越不划算）。
- 多机不需要 jcc 帮忙；getent 等 DNS + 静态 rendezvous 即可。**单节点**（numWorkers=1, gpuPerWorker=8）则完全不用这套，直接 `torchrun --nproc_per_node=8 --master_port=xxx`。
- 作业 schema（实测可用）：顶层 `numWorkers / gpuPerWorker / cpuPerWorker / memGBPerWorker / maxRetries`。
  - `cpuPerWorker` 别贪：空闲节点常已被系统/devpod 占 25~33 核，**设 ≤48** 才能放进全部空闲节点；贪到 64 会挑食、更难调度。

## 4. 训练相关坑（写过一次别再踩）

- **`dataset.stats_cache` 必须覆盖到 /fsx**：config 默认 `/local/evan/mot_stats/...` 是**每节点临时盘**，新节点上不存在 → 多卡会崩。
  提交时加 `dataset.stats_cache=/fsx/evan/mot_code/mot_pilot_v1/experiments/stats/monet_global_stats.json`。
- **路径三分**：`/fsx` 放代码+小产物（lustre，37T 但共享、别狂写）；`/local` 每节点热缓存（临时、会丢，放 HF/torch/triton 缓存 + anime 图缓存）；`/s3*` 放大产物（fuse 挂载，大文件读 OK，频繁随机写/rename 慎用）。
- **checkpoint**：train.py 只存**单文件 `last.pt`**（原子 `.tmp`→`os.replace` 覆盖），不累积。含 optimizer+EMA，**~22GB/个**（1.4B 可训参数 × fp32 矩）。`resume=true` + 固定 `checkpoint_dir` → 自动续训；`resume=true` 且无 last.pt 时从 step0 干净起。
  - retry 要 resume：`RUN_ID` 必须**写死**（别用 `date`，否则每次重启目录都变、resume 失效）。
- **anime 图走 R2/Cloudflare**：高聚合 QPS（如 8 节点 VAE 预缓存）会把 worker 打挂；在线训练 QPS 低 + 有 `/local` 磁盘缓存，一般 OK。32-rank 在线时留意 fetch 失败率（image_fetch.py 已加 FETCH_STATS 统计）。

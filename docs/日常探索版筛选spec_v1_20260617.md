## 0. TL;DR

- **口径**：GPIC **7M** + MONET-real **11M** + synthetic **3M** = **21M**。（原拟 6/11/3；Evan 把 synth 暂定 2M 又恢复 3M、6M→7M：synth 让出的口径最终回填，GPIC 拿 +1M。）
- **方法**：簇硬配额（多样性，`γ=0.6` 幂律 + 每非空簇保底）× 簇内 **Gumbel-top-k 加权无放回抽样**（质量，乘法式软权重）。**不从头重筛**，是母池子集。
- **多样性**：只在 20k 联合簇上拉平（`γ=0.6`+保底）；**不设类目目标**（沿用旧决策）。关键事实：render/3d 占 26% 是因它**簇最多**(4678)、不是簇更大(sz/avg=1.02)，单靠簇拉平压不动它，Evan 选不压。
- **质量软权重**：aes（软、不硬切）× 水印惩罚 × 唯一性(sscd_nn) × caption 丰富度 × 分辨率。**唯一硬切 = MONET/synth 的 `wk>源 p95`**（母池已切 >p98，再去 p95–p98 段）+ text-rich 惩罚减半。**不筛 NSFW**（只继承母池 ≥0.9 保险丝）。
- **源平衡**：MONET 源软拉平 `α=0.7` → laion+coyo ≈ **48%**（母池原生 68%）。
- **分辨率/课程**：保完整 256→512→1024；MONET **ge1024 尾部提权保量**；GPIC 自然分辨率（256 资产）；synth 全 1024。
- **产出**：单 manifest `t5_manifest/daily_v1/{gpic,monet,monet_synth}`（与 rich_v1 **同 33 列 schema** + 追加 `wk/sscd_nn/elig_256/elig_512/elig_1024`，可 union、可直接喂现有 loader）+ 每 stage 域配比 config（present_renorm）+ QC。纯 CPU、无 GPU。
- **1024 caveat**：256/512 的 18/27/15/40 caption 供给充足；**1024 的 T1/T4 不足**，训练配置不得直接沿用全阶段 18/27/15/40 当作“无重采样可行”。

## 1. 信号清单与来源（join 回 T3，rich_v1 的 33 列没有 wk/sscd_nn）

| 信号 | 来源（列） | 用法 |
|---|---|---|
| `cluster_id`(0..19999) + `dominant_cat` | rich_v1 | 多样性分层（簇配额 γ=0.6+保底）|
| `sub_source` | rich_v1 | MONET 源软拉平 α=0.7 |
| `aes`(jasperai/laion_improved) | rich_v1 | **软权重**（秩百分位，不硬切）|
| `wk`（水印概率） | **join `monet_manifest`**(by `id`) | **硬切 > 源 p95** + p80–p95 软降权（MONET/synth）|
| `sscd_nn`（最近邻 SSCD，越高越冗余） | **join `monet_manifest`** | **软权重**：越独特(低)越优先（仅 MONET）|
| `width/height` / `res_bucket` | rich_v1 | 派生 `elig_256/512/1024`；MONET ge1024 提权 |
| `has_t1..4` / `tok_*` | rich_v1 | caption 丰富度软权重；档配比 QC |
| `wk` 阈值 | `monet_wk_thresholds.json`（各源 p95/p98） | 硬切阈值 |
| `nsfw_max` | — | **不用**（Evan）|

> GPIC（`gpic_pass`）只有 `aes_laion_improved`，**无 wk/nsfw/sscd_nn**；其质量杠杆 = aes（软）+ 簇多样性，冗余由母池 pHash/SSCD 跨源去重兜。

## 2. 选样机制（两层）

每域：① **簇硬配额**（多样性）② **簇内 Gumbel-top-k 加权无放回**（质量）。

**簇配额**（每域、每簇 c）：`q_c = floor_c + round(R · n_c^γ / Σ n^γ)`，`floor_c=min(FLOOR, n_c)`，`R=budget − Σfloor`，`γ=0.6`，`FLOOR=2`，cap 在 `n_c`，修正取整命中 budget。→ 小簇保底、大簇按 √-ish 压。

**簇内权重**（乘法式，逐图）：`w = f_aes · f_wk · f_uniq · f_cap · f_res`
- `f_aes`：域内 aes 秩百分位 → `AES_LO + (1−AES_LO)·pct`（`AES_LO=0.4`，软、低 aes 仍非零）。
- `f_wk`：`wk≤p80`→1；`p80<wk≤cut`→线性降到 `WK_MIN=0.5`；**text-rich 惩罚减半**。GPIC=1。
- `f_uniq`：`1 − UNIQ_PEN·sscd_nn`（`UNIQ_PEN=0.4`）。仅 MONET；GPIC/synth=1。
- `f_cap`：`0.9 + 0.1·(n_bands/4)`（n_bands=ΣhasT）。轻。GPIC=1。
- `f_res`：min(w,h)≥1024→1.5；ge512→1.1；else 1。仅 MONET/synth（GPIC 自然分辨率不加权）。

**Gumbel-top-k 无放回**（Efraimidis–Spirakis）：`key_i = log(u_i)/w_i`（`u~U(0,1)`，种子 `SEED=1234`），每簇取 `key` 最大的 `q_c` 张。全局向量化：按 `(group, −key)` 排序、组内 rank、取 `rank<q`。

## 3. 三域流程

**MONET → 11M**：join wk/sscd_nn → **硬切 `wk>p95`**（text-rich 用 p98 不额外切）→ **源预算** `budget_s ∝ N_s^0.3`（α=0.7，cap 在可用量，da4k 封顶 1.17 万，余量再分）→ 每源内簇配额(γ0.6+floor) → 簇内 Gumbel-top-k 按 `w`（含 f_res 提权 ge1024）。
**GPIC → 7M**：无硬切（母池已切底 10%）→ 簇配额(γ0.6+floor) → 簇内 Gumbel-top-k 按 `f_aes`（无 wk/uniq/res）。**自然分辨率**。
**synthetic → 3M**：**排 holdout** → 硬切 `wk>p95` → 按 `sub_source×tier` 分桶（tier=最高可用 band）→ 桶内按可用量比例配额（保留生成器/档分布）→ 桶内 Gumbel-top-k 按 `f_aes·f_wk`。全 ≥1024。

## 5. Stage 划分与采样配比（无 anime 的日常池）

分辨率课程沿用 v3：**256→512→1024**（Stage1a 256 预训→512 主训；Stage1b 512；Stage2 1024）。路由（资格）：256=全体（ge512 可降采）；512=MONET ge512（GPIC 退场）；1024=MONET min(w,h)≥1024 + synth。

**关键**：日常池**没有 anime**（全设计里 anime 在 512 占 50–65%、1024 是主力）。故 512/1024 只剩 real+synth。用 e2e dry-run 已验证的 **present_renorm**（去 anime/TextAtlas 占位、real+synth 重归一）域配比：

| stage | MONET | GPIC | synthetic | 说明 |
|---|---|---|---|---|
| 256 | ~0.747 | ~0.187 | ~0.067 | real 内 MONET:GPIC=80:20 |
| 512 | ~0.881 | 0 | ~0.119 | GPIC 退场 |
| 1024 | 0.40 | 0 | 0.60 | synth 主导高清 |

band-first（18/27/15/40）+ band→captioner 优先级 + 10% dropout 全沿用母池。**因静态池已内置簇/源平衡，运行时可把 `cluster_β`/`source_α` 调轻甚至关，避免双重拉平**（config 里 daily 默认 β=0.2、α=0.2）。

> ⚠️ **【2026-06-17 修订】** 实际训练线 complete_v1（daily+anime）的 **stage-256 real 内 MONET:GPIC 改用 11:7**（= 静态池 11M:7M 自然比，monet_real 0.397 / gpic 0.253），取代上表的 80:20（0.747:0.187）。上表是 daily 单独（无 anime）的历史 present_renorm；开训以 complete_v1 config（`configs/t5_sampling_complete_v1.json`）+ AAA 交付文档 §11.5 为准。

⚠️ **但 18/27/15/40 不能无脑套到 daily_v1 的 1024 阶段**：`daily_v1_qc.json` 按真实 `tok>0 且落档` 规则验证，1024 池（MONET≥1024 + synth，共 5.05M）中 T1/T4 供给不足，oversample_factor 分别为 **1.202 / 1.949**。这不是 manifest 构建错误，而是小池 + synth prompt 档位偏中短/中长导致的阶段性约束。训练侧必须显式选择：1024 单独改 band mix、允许受控重采样，或补/重选 1024 T4 供给。

## 7. 复杂度 / 运行 / 验证

- 纯 CPU jcc（`gpuPerWorker:0`，cpu32/mem256），`SEL=daily`。预计 ~20–40min（瓶颈是 join monet_manifest 取 wk/sscd_nn，沿用 `collect()` 全局 is_in）。**无 GPU**。
- 入口 `cluster/run_t5_select_in_pod.sh` 的 `daily` 分支 + `cluster/t5_daily_select_job.yaml`。先 smoke（MAX_SEL 小子集）校验逻辑，再全量；写 `daily_v1_tmp_$job/` 校验后原子切换。
- **QC**（`daily_v1_qc.json`）：簇覆盖（小簇没消失）、`dominant_cat` 分布、**source 占比≈48% 实测**、aes/wk/sscd_nn before-after（应右移/左移/更独特）、res 各桶 + **elig_1024 绝对量够不够 1024 阶段**、18/27/15/40 档配比在 21M 下的整体供给、以及 **stage 级 caption 供给**。注意：整体 21M 和 256/512 绿灯；**1024 的 T1/T4 绑定**，见 §8 caveat。

## 8. 已知 caveat

1. **1024 阶段 caption 配比待训练侧显式处理**：daily_v1 1024 可用池=5,049,529（MONET 2,049,529 + synth 3,000,000），按原 T1/T2/T3/T4=18/27/15/40 检查，T1 oversample_factor=**1.202**、T4=**1.949**，即 T1/T4 供给不足。**不要把 18/27/15/40 直接当作 1024 无重采样可行配置**。本轮先记录，不解决。
2. daily 是母池子集；**不重跑去重/聚类/SSCD**，复用既有标注（Evan 定）。
3. synth 无 cluster_id → 用 `sub_source×tier` 当多样性代理（synth 是 1024 锚池、非多样性主驱）。
4. 源软拉平 α=0.7 + 簇配额是两个交叉维度；**源占比由 source-budget-first 精确保证、簇多样性在源内**（避免 source×簇硬嵌套过约束）。QC 验证 source 占比。
5. GPIC 无 wk/sscd_nn → 仅 aes 软权重 + 簇多样性；水印/冗余靠母池清洗兜。
6. text-rich 保留自然 ~5%（"不考虑 TextAtlas"=不新增那个数据集，非删 real 带字图）；只对它减半水印惩罚。

## 1. anime 17-shard 偏斜（B7a）
**问题**：`training/dataline/manifest_index.py:shard_subset_for_rank` 按**整 shard** 分（`i % world == rank`）。anime 源只有 **17 个 parquet（29.6GB / 16.5M 行 / 144 列**，是含 caption+tag 的完整源，不是瘦索引）。world>17 时部分 rank 拿 0 个 anime shard → `domain_mix_renorm` 把它们的 anime 预算摊掉 → 全局 anime 占比掉（512/1024 anime 权重 0.65/0.80，掉得更狠）。当前 256 是 world=8<17 → **无偏斜**。

**两个修法**：
- ✅ **(推荐，零成本) 512 也跑 world≤16**：anime 17 shard ≥ 16 → 无偏斜。鉴于 256 已实测 1×8 因 Socket/无IB 比 4×8 更划算（多机扩展效率 ~24%），**512 大概率也会 ≤2 节点**，那就天然无此问题，啥都不用做。
- 🔧 **(仅当 512 要用 >16 GPU) 重分片 17→64**：已备好 `jobs/reshard_anime_for_512.yaml`（驱动 `experiments/exp_scripts/reshard_anime_parquet.py`，行级 round-robin、流式低内存、写到**新路径** `/s3/.../anime_core_ditv04_ct_soft_resharded64/data`，不碰源、不碰在跑训练）。跑完后，**新建一个 512 专用 sampling config**（复制 `t5_sampling_complete_v1.json`、把 `anime_caption_source` 指向 resharded 路径）给 512 用——**切勿改线上那份共享 config**（256 在跑会读到）。

## 2. 多卡采样 DTensor bug（B7b）
**问题**：`networks/arch_mot.py` 采样 KV-缓存路径（`forward_und_capture`/`forward_gen_cached`）直调自定义方法、绕过 `__call__` → 多卡 FSDP2 下 all-gather 不触发 → DTensor 混算崩。当前**单卡 eval 不受影响**（已实测可用，含 B1）。
**状态**：补丁 + CPU 单测已落盘（durable）：
- 补丁 `experiments/patches/dtensor_sampling_dispatch_fix.patch`（仅 `networks/arch_mot.py`，+16/-3，纯 plumbing：`MoTDecoderLayer.forward` 加 `und_capture`/`gen_cached` 两个 mode 分支，`precompute_und_cache`/`forward_gen_cached`(transformer 级) 两处调用改走 `layer(..., mode=...)`；被调子方法一字未改 → 单进程数值零改动）。
- 单测 `experiments/patches/test_sampling_dispatch_fix.py`（**对打补丁后的 arch_mot.py** 运行）。已验：T1/T2 layer 级 `__call__(mode)` vs 直调 **bit-identical**；T3 transformer 级采样路径 vs joint forward 7 组配置 max|Δ|≤6.85e-7；T4 `joint` 默认/显式/内部三路 bit-identical；既有 `scripts/test_arch_changes.py` 全过。
- ⚠️ 本环境无多卡，**没测到真正的 FSDP2 DTensor crash**——只证明「改走 `__call__` 是纯 plumbing、单进程零改动 + 与 joint 等价」；真正多卡采样跑通须 H100 上验。
**上线方式**：`git apply experiments/patches/dtensor_sampling_dispatch_fix.patch` 后跑该单测确认，**仅在 512 多卡 eval 前、且避开在跑 run 的 maxRetries 重启窗口**再合入（`arch_mot.py` 是在跑训练会读到的文件；虽前向逐位零影响，仍属改在跑文件，须 Evan 确认时机）。

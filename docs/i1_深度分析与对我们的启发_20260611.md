## 0. TL;DR（对我们最重要的 5 句话）

1. **i1 最大的价值不是模型，是方法论**：300+ 个单变量受控实验（256 分辨率、500K 步、固定 baseline、3 个便宜 benchmark 做信号），消融花的算力 ≈ 最终模型的 6 倍。我们 pilot 应该直接抄这套"便宜消融单元"打法，这正好落实 lead 的"单次实验 < 1 周"。
2. **它的 caption 结论与我们当前数据方案直接冲突**：i1 证明"只用长 caption 训练 + 推理时 LLM 改写短 prompt"显著强于"短/中 caption 为主"（GenEval 0.73 vs 0.47）。我们 v2 方案写的是"短/中为主 + 少量长"——建议重审（§4.1）。
3. **它给了我们一份可白嫖的资产**：166M 条 Qwen3-VL-30B-A3B 长 caption（含 YFCC 97.9M、ImageNet-22K 13.7M）全部开源在 HF，和我们 backbone 同源（Qwen3-VL）。realistic 底子数据多了一个候选/补充源。
4. **架构上可抄的便宜组件**：long skip、去 AdaLN、"加大 text adapter 而不是加 text encoder"（这三条 i1 跨尺寸验证、强先验）；sandwich norm、sinusoidal+RoPE（i1 只在小尺寸见效、放大后趋势不一致，弱先验，当稳定性默认而非赌涨分）。详见 §4.3.1–4.3.3。
5. **不要照搬它的目标函数**：i1 优化的是 prompt-following 类 benchmark（且 prompt 改写明显带考试技巧），作者自己承认画质/美感明显不如 Qwen-Image。我们打 Anima 靠的是二次元美感和体验，i1 的配方解决"底子和指令跟随"，解决不了"好看"。

## 1. i1 是什么（30 秒版）

| 维度     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 模型     | **3B 纯 T2I 扩散模型**（dual-stream MMDiT：depth 29 / hidden 2016 / 28 heads；消融用 XL：hidden 1152） |
| 组件     | FLUX.2 VAE ＋ **T5Gemma-2B 冻结 text encoder** ＋ 2 层 transformer adapter；**无 AdaLN/无噪声条件**；long skip；sinusoidal+RoPE；共享 sandwich norm |
| 目标函数 | flow matching（lognorm(0,1) 采样 timestep），velocity prediction |
| 数据     | 12 个全公开数据集 168M 图（7 真实 + 3 合成 + 2 文字渲染），最终去掉 iNaturalist 剩 11 个，**所有数据集等权采样** |
| Caption  | Qwen3-VL-30B-A3B (FP8, vLLM) 生成**纯长 caption**（"Describe the image in detail using one paragraph"），每图 1–5 条 |
| 课程     | **256（2M 步, bs512）→ 512（0.5M 步, 9.7M 图）→ 1024（0.3M 步, bs128, 4.3M 图, timestep shift 3.33）** |
| 算力     | 最终模型 ≈ 383+174+151 ≈ **708 小时 × TPU v5p-128**；消融 300+ 个 × ~31h × v6e-64（总计 ~70 万 TPU 时） |
| 成绩     | 5 benchmark 均分 83.7：比此前最强 fully-open（BLIP3o-NEXT 系）**高 ~29.5 个百分点**；超过 FLUX.1-Dev(12B)、HiDream-I1(17B)；距 Qwen-Image(20B) ~1.6 分 |
| 开源     | 权重（JAX+Torch）、训练代码（JAX/TPU）、**166M captions**、数据管线、全部消融。Torch 训练代码和多长宽比版本"将出未出" |

**它不是什么**：不是 MoT、不是 UMM、没有理解分支（text encoder 在模型外面、冻结）——和 nano-T2I 同一物种，但更大、更系统。对我们而言：**nano-T2I 仍是代码级参考（torch），i1 升级为"决策级参考"（每个超参/数据选择背后都有消融背书）**。

## 2. 它的"成功"成色拆解：三分真实力、一分考试技巧、一分生态位

### 2.1 真实力①：方法论（最值得抄）

- **固定一个便宜 baseline**（256 分辨率、500K 步、bs512、cross-attn XL），每次只动一个变量，**改动不累积**，最后把有效的拼成 i1。
- **3 个便宜 benchmark 当训练信号**：DPG（细粒度跟随）+ PRISM（跟随+美感）+ LongText（文字渲染），全是 VLM 判分、可自动化。GenEval 只在最后报告（并明确指出它和人类判断错位、易被 BLIP3o-60K SFT 刷分）。
- **算力分配哲学**：~6/7 的算力花在"搞懂哪些选择重要"，1/7 花在最终模型。结果是论文里 10 条 finding 每条都有数字背书，社区可以放心继承。

### 2.2 真实力②：数据配方（结论可直接当先验）

| #    | i1 finding（含证据）                                         | 强度                          |
| ---- | ------------------------------------------------------------ | ----------------------------- |
| D1   | **Captioner 质量显著影响下游**（Qwen3-VL-30B-A3B > 4B > 2.5-VL > 2-VL） | 强                            |
| D2   | **纯长 caption 训练 + 推理改写 > 任何短/混合方案**：100% 长 + 改写 = 0.73；100% 短 + 原始短 prompt = 0.47；训练-推理 prompt 长度分布必须对齐 | 强，但有产品侧 caveat（§4.1） |
| D3   | **数据集等权采样（每源 cap 到同量级）≈ 最优**；任何单源 ×3/×5 上采样都不能超过均衡配比 | 强                            |
| D4   | **剔除最差源有纯增益**（去 iNaturalist 全面涨分）；窄域数据（动植物特写）拖后腿 | 中-强                         |
| D5   | **重复数据几乎免费**：多样混合下，每源砍到 0.4M 张（共 4.4M 张、重复几十 epoch）性能只掉一点 | 强（对省存储/预处理极有用）   |
| D6   | **高分辨率阶段不需要广覆盖**：512 只用 9.7M、1024 只用 4.3M 张，能力不丢 | 强                            |
| D7   | 真实/合成/文字渲染三类数据**互补**：去掉真实掉 DPG、去掉合成掉 PRISM、文字渲染只能靠专门数据（TextAtlas） | 强                            |
| D8   | 文字渲染能力主要在 **512 阶段**长出来（LongText 0.75→0.92），1024 阶段增益很小 | 中                            |

### 2.3 真实力③：架构筛选（都在 3B 内验证过）

| #    | finding                                                      | 对应 i1 选择                                  |
| ---- | ------------------------------------------------------------ | --------------------------------------------- |
| M1   | encoder-decoder（T5Gemma）≥ decoder-only LLM/VLM ≥ CLIP 作 text encoder；instruction tuning 无所谓、更大 encoder 不一定更好 | T5Gemma-2B（冻结）                            |
| M2   | **多 text encoder 的收益 ≈ 单 encoder + 更大 adapter**（2.6M MLP → 2×17.2M transformer block 即可，>2 块边际递减），且不增加序列长 | 单 encoder + 2 块 transformer adapter         |
| M3   | **AdaLN/噪声条件收益边际**（flow matching 下），删掉省一大块参数 | 完全去掉 AdaLN                                |
| M4   | **long skip connections 改善性能-参数 trade-off**（U-ViT 老设计，现代模型弃用是个错误）；附录消融"连哪些层"——**对称默认（深度 29 → 层 1–14）≥ 所有试过的变体**，跨 5 宽度 + 跨多 backbone 都成立，去掉尤其掉 DPG/LongText | 用                                            |
| M5   | **dual-stream > single-stream > cross-attn**（同参数量下，5 个宽度扫过） | dual-stream                                   |
| M6   | sandwich norm 稳 **residual update**（与 QK-norm 稳 attention logits 不冗余）；sinusoidal(绝对)+RoPE(相对) 并用补绝对坐标。⚠️ **i1 自承：这两条 + 跨流共享 norm 放大尺寸后趋势不一致**（附录 L1830）→ 弱先验 | 用，但按 §4.3.3 改造（gen-only / 不动 MRoPE） |
| M7   | VAE：**FLUX.2 最均衡**；VA-VAE（语义对齐型）DPG 最高但**文字渲染崩**（重建保真度差） | FLUX.2 VAE                                    |

### 2.4 考试技巧成分（要诚实看待）

- **推理时 prompt 改写是个高度工程化的 metaprompt**（仓库 `torch_inference/metaprompt.txt`，~1500 词 + 16 个 few-shot）：明示"物体间留 negative space 以便检测器分离"、"文字高对比度以便 OCR 检出"——**直接面向 GenEval 检测器和 OCR 评测机制写的**。CFG 开到 12（同行 4–7）。
- 但他们做了公平性检查：给 Lumina-2.0 / SD3-Medium 同样的高 CFG 和改写 prompt，**对方不涨分**——说明"长 caption 训练 × 推理改写"是训推协同设计的系统收益，不是通用的考场外挂。改写只对"按长 caption 分布训练过的模型"有效。
- **美感/人类偏好未测**，作者承认画质明显逊于 Qwen-Image，复杂场景人脸/肢体仍崩。它赢的是 prompt-following 卷面分。

### 2.5 生态位（"成功"的另一半）

fully-open 赛道此前最强是 BLIP3o 系（均分 ~54），i1 一把拉到 83.7——**赢在选了一条没人认真卷的赛道，用学界免费算力（TRC）+ 彻底开源（166M caption 是真金白银的社区贡献）拿下心智**。我们"开源数据超 Anima"的故事线与之同构（§4.5）。

## 4. 对我们的具体启发（按优先级）

### 4.1 ✅【P0，影响本周数据需求】重审 caption 长度策略

i1 的证据链：训练 caption 长度分布必须和推理 prompt 分布对齐；长 caption 训练学到的组合能力更强；短 prompt 的缺口用推理时改写补（0.73 >> 0.47）。

对我们的修正建议：

1. **二次元 16M 重新 caption 时，长 caption 应为主力**（而不是"短/中为主"）。用手头最强的 Qwen3-VL（30B-A3B FP8 + vLLM，i1 的 caption.py 可直接参考）而不是 4B。
2. **但不要 100% 长**——两个我们特有的约束：① Anima 的用户生态是 danbooru tag prompt，i1 没测过 tag 式输入；② 部署端不一定总挂着改写器。建议 **长:中:tag ≈ 60:20:20 起步**（i1 表里 60% 长 caption 在"短 prompt + 重复"下也是最优档），然后在消融单元里扫这个比例。
3. **推理改写是我们的天然优势**：i1 要外挂 Qwen3-4B 做改写，而**我们模型里自带冻结 Qwen3-VL 语言分支**——同一个模型既改写又生成（tag → 长描述 → 生成），这是对 Anima 的差异化卖点，也是"MoT 统一架构"故事的落地点。建议把"自改写"列为 roadmap 上的轻量 feature。
4. 与 Anima 头对头评测时，**同一批二次元 prompt 按三档输入分别测：原始（tag/短）/ 轻改写 / 长描述改写**，两个模型都跑全三档。只报"改写开"会被质疑，只报"改写关"则埋没长 caption 训练的真实收益；三档矩阵同时回答"真实用户体验"和"模型上限"两个问题。

### 4.2 ✅【P0，影响实验设计】抄它的"便宜消融单元"

把我们所有架构消融标准化成一个固定单元，例如：**256 分辨率、固定数据混合（MONET 子集 + anime 子集）、100–200K 步、bs 512、DPG+PRISM+LongText+自建二次元小集**。

- 我们排期里的消融（RAE 闸门后的接入、AdaLN 去留、long skip、adapter 大小、CE:MSE 配比、mask 方案）全部进这个单元跑，一周多个。
- i1 已替我们在 3B 验过的结论（M2–M5；**M6 的 sandwich/sin 是例外，只在小尺寸见效，见 §4.3.3**）直接当先验，**不重复消融**；只消融与我们独有变量交互的部分（MoT/冻结分支/RAE/二次元域）。
- 注意它消融在 500K 步才分得清优劣，我们 100–200K 步的版本要先校准"早期信号和后期排序是否一致"（拿 2–3 个已知结论复测一次即可）。
- 可选诊断项（一个消融单元的成本）：同数据同预算跑一个 **T5Gemma-2B 条件的纯 T2I 对照**，量化"冻结 Qwen3-VL 作为条件源"相对最优 text encoder 到底差多少——这是给 §6.1 的质疑提前准备我们自己的数字，差距小则反驳有据，差距大则尽早知道要靠 adapter 补。

### 4.3 ✅【P1，架构 backlog 加三个便宜项】

1. **接口加可训练 text adapter（最重要的一项）**：在冻结 Qwen3-VL 文本特征 → 生成塔之间插一小块可训练 transformer（~35M），把语言特征整形成扩散友好的条件。i1 的 M2 证明"加大 adapter ≈ 多接 encoder"；对我们更关键——文本侧全冻结，**adapter 是文本信息唯一可学习的整形通道**，收益预期比 i1 更大。**详细设计、init、双向 trick、RoPE 注记、实验排布见下方 §4.3.1。**
2. **生成侧 long skip**：浅层 → 对称深层的跨深度捷径（U-ViT/i1）。i1 Finding 2 跨宽度 + 跨 backbone 稳定涨分，尤其 DPG/LongText。我们只做 **generation-token-only** 版、zero-init gated 保 baseline。**详细设计、消融、伪代码见下方 §4.3.2。**
3. **去 AdaLN 消融**：flow matching 下噪声条件可删（i1 + Sun et al. 2025；代码核实过：no-AdaLN 路径下 t_emb 虽仍被计算但完全不进 block，**真·零噪声条件**）。**但注意与 nano-T2I 的 AdaLN-zero 初始化路线冲突**，二选一消融定夺；删掉的参数还给 transformer 层。
4. **norm 与位置编码（顺手定，不抢消融预算）**：QK-norm 自带（Qwen3 复制）；**sandwich norm 做 generation-only、直接进 baseline**；位置编码主线**保留 Interleaved-3D-MRoPE 不替换**；i1 的绝对 sinusoidal 仅作条件触发的低优先级消融。**详见下方 §4.3.3。**
5. **VAE/latent 接入的工程细节（适用于 VAE 基线和 RAE 闸门）**：i1 对 latent 做**逐通道 mean/std 归一化**，统计量取官方值——FLUX.2 是先 2×2 space-to-depth 重排成 128 通道、按 128 维官方统计归一化后再排回 32 通道；Qwen-Image 是 16 维逐通道 mean/std（见其 `jax/vae/vae.py`，可直接抄）。两个提醒：① 我们接 VAE 时不要只做全局 scale，按它的逐通道方案来；② **官方统计量来自自然图分布，二次元域可能偏移**——VAE gate 里加一步"用我们的数据混合重估 latent 统计并与官方值对比"，偏移大就用自己的。这与 RAE 方案里"按通道统计归一化"的既有计划同构，可共用脚本。

#### 4.3.1 生成侧 text adapter —— 详细设计（上方第 1 项的展开）

**定位与为什么我们没有**：i1 的「text encoder + adapter」= 外挂冻结 T5Gemma-2B + 2 块 transformer connector，长在 dual-stream 的**文本 stream 边界**上。我们没有这个边界——MoT 是共享注意力、单序列，文本 token 的 K/V 由**冻结** Qwen3-VL 投影算出，生成塔（`add_q`）直接 attend，**文本侧对生成塔零可训练整形**，比 i1 的 raw+linear 基线还裸。所以不是照搬模块，而是把"给文本特征一个可学习整形通道"翻译成 MoT 形态；预期收益 > i1（从 0 到 1、唯一可学通道）。

**Variant A（起步，贴 i1，验 M2）**

| 项        | 取值                                                         |
| --------- | ------------------------------------------------------------ |
| 输入      | 冻结 Qwen3-VL 文本 hidden states `H_t [B, L_t, 2048]`，第一版用末层 |
| 结构      | 2 层 transformer block，宽 2048（i1 的 >2 块边际递减，别贪） |
| norm/激活 | RMSNorm + QK-norm + SwiGLU（沿用生成塔规范，第一版**保留**） |
| 位置编码  | adapter 内**默认不加 RoPE**（见下注），留可选开关            |
| attention | 双向 self-attn（见"双向 trick"）                             |
| 注入      | 残差 `T' = H_t + Adapter(H_t)`，**末层投影 zero-init** → step0 ≡ baseline |
| 消费      | 生成塔噪声 token attend `T'`；理解分支仍用原始 `H_t`（互不污染） |
| 代价      | ~35M，<2.5% 生成塔，算力/显存可忽略                          |

zero-init 残差是关键去风险点：初始严格等价当前 baseline，纯增量、训练只会让它变好，契合"先稳 baseline、别堆创新"——所以它可以早进 baseline 也不会伤害初始性能。

**⚠️ RoPE 注记**：Qwen3-VL 输出的 hidden 已经过 LM 内部 RoPE、本身带位置信息；i1 的 text adapter 本质是普通 transformer connector，位置主要交给后续 backbone 处理。adapter 内再叠一层 RoPE 多半冗余甚至冲突，**第一版默认关**，仅作可选开关**单独**验，**不要和"是否双向"混进同一轮主实验**（避免混淆变量）。

**双向 trick（我们该做、i1 不必做）**：Qwen3-VL 是 decoder-only，文本特征是**因果**的；i1 的 M1（encoder-decoder 双向 > decoder-only）那段 gap 部分来自这里。把 adapter 设**双向**，等于在因果特征上补一层双向重编码，直接回填这段 gap——这是冲着 §6.1 不利 finding 的针对性设计。

**Variant B（兜底，更省）**：不加整块 transformer，逐生成层给文本 K/V 加 zero-init 的 LoRA 式 ΔK/ΔV，保留逐层特征匹配，参数更小、风险更低。A 收益不明显再退 B。

**实验排布**（进 §4.2 的 256 便宜消融单元）：

- day-1 baseline 维持无 adapter（与现方案一致）；adapter 作为**架构消融第 1 项**。
- 第一轮主实验**单轴**：`{无 adapter} vs {A·因果} vs {A·双向}` → 一次回答"adapter 有没有用"+"双向回填多少 M1 gap"。**RoPE 全程关、不交叉。**
- RoPE-in-adapter 作独立小开关，要测时单列一格（`A·双向 −RoPE` vs `+RoPE`），不进主轴。
- 配 §4.2 的 T5Gemma 诊断基线 → 量化"frozen Qwen3-VL 当 text encoder 亏多少 + adapter 补回多少"，给 §6.1 备好自家数字。

**伪代码**（命名对齐 Cosmos3 `add_q/k/v`，K/V 实际接法依你们代码）：

```python
H_t = qwen3vl_text_hidden(text_tokens)   # [B, L_t, 2048] 冻结、因果、已带位置信息

# 生成侧 text adapter（可训练 ~35M）：双向 + RMSNorm/QK-norm/SwiGLU；RoPE 默认关
T = H_t
for blk in adapter_blocks:               # n = 2
    T = T + blk(T)                       # blk 末层 proj zero-init → 初始 T ≡ H_t
T_cond = T

# 进 MoT 共享注意力：生成塔文本 K/V 来自 T_cond（而非冻结 to_k/to_v）
# K/V 投影可复用 add_k/v_proj 或新建 text_k/v_proj；理解分支仍用 H_t
```

#### 4.3.2 生成侧 long skip —— 详细设计（上方第 2 项的展开）

**定位与为什么我们没有**：long skip = U-Net→U-ViT 的跨深度捷径——浅层 layer i 的激活存下，深层对称 layer L+1−i 取回融合（U-ViT/i1 = `Linear(concat[current, skip])`，前半层 in-blocks 存、后半层 out-blocks 对称取）。i1 Finding 2：跨 5 宽度 + 跨多 backbone 家族稳定涨分，去掉尤其掉 DPG/LongText；附录消融"连哪些层"——完全对称（深度 29 → 层 1–14）是默认，**所有变体都没稳定超过它**。我们生成塔逐层复制 decoder-only Qwen3-VL，LLM 传统无长跳跃、现代 DiT 也多丢了（i1 称之为被低估的错误）；叠加"全序列 skip 污染模态边界 + AR/KV-cache 工程 + packed-sequence 显存"三重顾虑，UMM 一直忙 unified/mask/routing/data、**没系统测这个生成侧 DiT trick**——不是反证。

**两条 i1 不需要管的约束**：

- **只动生成/噪声 token，冻结理解塔绝不碰。** 我们非对称 mask（文本/干净图不看噪声）保证改 gen token 无法回流污染冻结路径；且 generation-only 只缓存 gen token 激活，比全序列省显存，也绕开 AR/KV-cache 复杂度（扩散去噪前向非自回归、不走增量 cache）。
- **生成塔从预训练 Qwen 权重起**（无 skip 残差结构下训出来的），必须 zero-init/gated、step0 严格等价无 skip baseline，别冷启动破坏它。

**LS-A（主方案）**

| 项   | 取值                                                         |
| ---- | ------------------------------------------------------------ |
| 范围 | 仅生成/噪声 token；对称 skip（层 i ↔ L+1−i，L≈28 → ~14 条）  |
| 位置 | 后半层进 MoT layer、生成分支 **input-norm 之前**融合，再照常走 gen 专属 QKV/O、norm、MLP |
| 融合 | `x_gen += gate · ZeroInitLinear(concat(RMSNorm(x_gen), RMSNorm(skip_gen)))` |
| init | gate（或 ZeroInitLinear）**zero-init → step0 ≡ 无 skip baseline**；concat 前各自 RMSNorm 压浅/深层尺度差（比 i1 原版 replace 形更稳） |
| 代价 | 仅缓存 gen token 前半层激活，配 activation checkpointing 可控 |

**消融（baseline + 2 变体，控制在 2–3 内）**：

| 组                    | 改动                                                | 目的                                                         |
| --------------------- | --------------------------------------------------- | ------------------------------------------------------------ |
| baseline              | 无 long skip                                        | 锚点                                                         |
| **LS-A（主）**        | generation-only 对称，zero-init gated delta（上式） | 测生成侧长跳跃是否稳定涨分，重点看 DPG / LongText / anime 线条结构 |
| **LS-B（更省/诊断）** | 同 LS-A，只连最外侧 ~1/3 层                         | 砍激活显存；判断收益是否主要来自最长距离的 skip              |

LS-A 正向后再**二选一**深究（不进第一轮，省算力）：换 i1/U-ViT 原版 replace 形 `Linear(concat)` 看是否更强；或 skip delta 只进 MLP 前不进 attention 前，判断收益要不要改 K/V。

**伪代码**（仅生成 token 的残差流）：

```python
skip_bank = []
for i, layer in enumerate(gen_layers):        # L ≈ 28
    if i < L // 2:                            # 前半：存
        x_gen = layer(x_gen, ...)             # 正常 MoT 层
        skip_bank.append(x_gen)               # 存该层 gen-token 输出
    else:                                     # 后半：对称取回 + 融合（在 input-norm 前）
        skip = skip_bank.pop()                # 对称浅层（层 L+1-i）
        delta = ZeroInitLinear(concat(RMSNorm(x_gen), RMSNorm(skip)))
        x_gen = x_gen + gate * delta          # zero-init → step0 ≡ baseline
        x_gen = layer(x_gen, ...)             # 再走该层 attention / MLP
# 文本 / 理解 token 不进 skip_bank、不被融合
```

**排序与 go/no-go**：排在 text adapter（§4.3.1）之后；两者正交（文本条件 vs 生成侧深度建模），算力够可并行但**分开归因**。判据：256 稳定涨 → 进 512 主训；否则不为一个 T2I trick 给 UMM 主干加复杂度。

#### 4.3.3 norm 与位置编码 —— 最终决定（上方第 4 项的展开）

**前提（重要）**：long skip / 大 adapter / 去 AdaLN 是 i1 跨多尺寸验证过的强先验；而 sandwich norm、sinusoidal+RoPE、跨流共享 norm 这三条，i1 **只在小 baseline（XL/2）见效、附录自承"放大尺寸后趋势不一致"**（main.tex L1830）→ 弱先验。所以下面两条都"顺手定、不押注 benchmark、不抢消融预算"。

| 项                | 决定                                                         | 消融成本        |
| ----------------- | ------------------------------------------------------------ | --------------- |
| QK-norm           | Qwen3 复制自带，无需动作（稳 attention logits）              | 0               |
| **Sandwich norm** | **gen-only、bake 进 baseline**：仅对生成/噪声 token 的生成分支，`x_gen += RMSNorm(sublayer(RMSNorm(x_gen)))`（attn 与 MLP 各一次）；冻结理解侧（pre-norm Qwen3-VL）不碰。留 config 开关 | **0**（默认开） |
| **位置编码主线**  | **保留 Interleaved-3D-MRoPE**，不替换、不动文本/理解侧       | 0               |
| **绝对坐标 bias** | **可选 / 低优先级**：仅生成 latent/noise token 加 `x_gen += α·Sin2D(h,w)`，α zero-init、**AR 分桶感知**（非方图 square-grid） | 1（条件触发）   |
| adapter RoPE      | 不默认加（adapter 重点是双向重编码，见 §4.3.1）              | 0               |

**为什么 sandwich norm 值得、且 gen-only**：QK-norm 稳的是 attention logits，sandwich norm 稳的是 **residual update 尺度**，两者管不同的事、不冗余。我们去了 AdaLN、又往塔里灌动态范围大的 noise latent（不同 timestep）+ 后续 VAE/RAE latent 域漂，生成侧残差最容易涨飞——sandwich norm 是便宜保险。但**只能加生成塔**：全局加会改动冻结 Qwen3-VL 理解/文本路径的激活分布。定位是**稳定性、不是涨分**（i1 跨尺寸没复现 benchmark 收益）；下行风险近零（Z-Image/CogView 产线在用），所以直接进 baseline、不单独占消融格，万一早期 loss spike / 梯度异常 / latent 域切换不稳再用开关关掉。（不采用 gated-delta 版：对纯稳定性措施过度设计，且我们写进 baseline 而非往已有 run 嫁接，gen-only scoping 已保护冻结侧。）

**为什么位置编码不照搬 i1**：i1 的"RoPE"本就是 Multimodal-RoPE，它的 finding 是"在 (M)RoPE 之上再叠 sinusoidal **绝对**位置"——RoPE/MRoPE 是**相对**位置（只影响 Q/K 注意力几何），sinusoidal 把**绝对**坐标塞进 residual/value/MLP，两者正交。我们的 Interleaved-3D-MRoPE（文本 1D / 理解图 2D / 生成图独立 `T_gen=max(context_t)+2048`）维护了文本-理解-生成的**统一时空坐标体系**、且兼容冻结 Qwen3-VL，对 UMM/interleaved/edit 比 i1 的方图 2D-sin+RoPE 更合适——**这是承重墙，不替换、不混进文本/理解侧**。想借 i1 的绝对坐标，就只做上表第 4 行那个生成侧小消融，且必须 AR 分桶感知、不能照搬方图 square-grid 插值；只在**文字渲染 / 精确版面**成为明确目标时才跑。

### 4.4 ✅【P1，给数据 team 的增量需求】

1. **源级 cap + 等权**：MONET 是 9 个子源拼的——要求数据 team 保留子源标签，配比时对子源 cap（防单一爬虫源垄断）；i1 的"×3/×5 上采样任何单源都不赚"是现成依据。
2. **做一次"减最差源"审计**：照 i1 的单源训练法（或便宜替代：单源小模型/聚类查看），在 MONET/GPIC 里找我们的"iNaturalist"（窄域、低质子源）剔掉。
3. **i1-captions 直接利用**（HF: zlab-princeton/i1-captions，12 个子集 ~166M 条）：YFCC 97.9M 长 caption 现成可下，作为 MONET/GPIC 之外的 realistic 补充或 caption 质量对照（同 Qwen3-VL 家族，风格统一）。
4. **文字渲染子集提前到 512 阶段**：i1 显示文字能力主要在 512 长出来（D8），我们 Stage 2 (512→1024) 引入文字渲染数据的计划方向对，但应在 512 就加入而非等 1024；TextAtlas / RenderedText 是现成源（注意 RenderedText 原生分辨率低，1024 阶段要丢）。
5. **存储焦虑解除**：按 D5，realistic 数据如果预处理/存储吃紧，每源砍到 1–2M 张高质量子集即可，重复采样无碍。

## 6. 风险与未决问题

1. **T5Gemma > Qwen3-VL（作 text encoder）这个 finding 对我们不利**：纯 T2I 视角，我们的冻结 Qwen3-VL 不是最优文本条件源（i1 里 decoder-only 略逊于 encoder-decoder）。缓解：① 差距不大且大 adapter 能进一步缩小（i1 附录在大 adapter / 去 AdaLN 设定下趋势不变，但绝对差缩小）；② 我们选 Qwen3-VL 是为统一理解+后续能力，不是单为 T2I——这点在对外讲故事时要主动说清楚，避免被 reviewer/同事拿 i1 反问。具体对策见 §4.3.1「生成侧 text adapter」——adapter 设双向正是冲着这条 finding 里的 M1（encoder-decoder 双向 > decoder-only）成分去的。
2. **i1 全部结论来自自然图+英文域**，二次元域（平涂、线稿、tag 文化、日文文字渲染）无任何验证——所有先验在我们域里都要打折，关键几条（caption 长度、等权混合）值得在消融单元里复测。
3. 它的 1B 版本、多长宽比版本、torch 训练代码"即将放出"——**值得设个跟踪点**，尤其 1B 版（和我们生成分支 ~1B+ 体量直接可比）。

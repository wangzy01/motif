## 2. eval 总体方案（三层）

调研结论（[公司参考代码索引](公司参考代码索引_v1_20260619.md)）：**公司有的是"打分器"，没有的是"公开 benchmark"**。

**(A) 打分器层 — 公司全有现成，直接借/抽类，别重写**
FID·CLIP·HPSv2 (`piFlow_ReFL/lakonlab/evaluation/metrics.py`) · HPSv3 (`naifu/evaluation/hps_v3`，本地 reward 模型) · VQAScore (`piFlow .../vqa_score.py`, clip-flant5-xxl) · ImageReward (`Villiam-ImageReward`, `RM.load().score()`) · 美学 (`aesthetic-score`, pip/FastAPI) · anime tagger (`tagger-inference`, 29k booru tag)。

**(B) 公开 benchmark — 公司一个都没有，需自拉官方 repo + 我们采样器出图**
GenEval（`djghosh13/geneval`, Mask2Former）· DPG-Bench（mPLUG/VQA dense prompt）· PRISM（**先确认具体版本**，见 §3.6）· MJHQ-FID · GenAI-Bench(用 VQAScore) · T2I-CompBench · PickScore。

**(C) anime 专项 — 公司最有积累，拼装**
`tagger-inference`(概念/角色命中率) + `aesthetic-score`(美学) + `naifu/evaluation/concept_v1`(角色/画师，需把内部生成换成读我们的图) / `concept_v2/eval_aesthetic.py`(post-hoc 美学)。evalset 采样思路参考 `Concept-Eval/tags_eval`(按 tag 频率平衡)。

**(D) 跑图框架**：我们 [model_mot.generate_samples](../networks/model_mot.py)（prompts→pixels）是天然入口；骨架借 `qfty`（轻量多 GPU 分片，打分阶段自补）；`piFlow tools/test.py` 是完整在线评测但绑 mmcv/mmgen、改造大、不取。

## 3. eval 阶段1 实施计划 ⭐（消融 go/no-go）

### 3.1 目标与范围
- **目标**：对 256 四版消融（v1/B1/B2/B3）的 ckpt 出一张**横向对比表**，给 100–200k 步 go/no-go 信号；并给 noise-shift 拍板。
- **范围内**：anime 专项（tagger 命中 + 美学）· prompt-following（DPG + PRISM **子集**，各 ~100–200 prompt 求快）· 固定-sigma 网格 eval（noise-shift）。
- **范围外**（留阶段2）：GenEval 全量、MJHQ-FID、HPSv3/ImageReward 全套、DPG/PRISM 全量。
- **原则**：全部放 [experiments/eval/](../experiments/)（新目录），**不碰** train.py/model_mot/dataline 核心；scorer 用独立进程/服务，不进训练 venv 强依赖。

### 3.2 模块 / 目录设计（新增，不碰核心）
```
experiments/eval/
  run_eval.py            # 主入口：加载 ckpt → 单卡出图 → 打分 → 聚合成对比表
  fixed_sigma_eval.py    # noise-shift 拍板（固定 sigma 网格的 v-pred MSE）
  prompts/
    dpg_subset.jsonl     # DPG-Bench 子集 ~150
    prism_subset.jsonl   # PRISM 子集 ~150（待确认版本）
    anime_evalset.jsonl  # 自建 anime evalset（tag 频率平衡，含目标 tag/角色标注）
  scorers/
    tagger_score.py      # 接 tagger-inference：生成图→tag→与目标算命中率
    aesthetic_score.py   # 接 aesthetic-score
    (dpg_vqa.py / geneval 留阶段2)
  results/<ckpt_tag>/    # 出图 + per-prompt 分 + 汇总 metrics.json + 4 版对比表.md/html
```

### 3.3 三个评测维度
| 维度 | prompt 来源 | 评测器 / scorer | 产出 |
|---|---|---|---|
| **anime 专项**（最相关） | 自建 anime_evalset（参考 `Concept-Eval/tags_eval` 按 tag 频率平衡采 ~150，标注目标 general tag + 角色） | `tagger-inference`(命中率=‖预测∩目标‖/‖目标‖，角色命中) + `aesthetic-score` | 概念准确率 / 角色命中 / 美学分 |
| **prompt-following** | DPG 子集 + PRISM 子集 | DPG/PRISM 官方评测器（VQA-based） | prompt 跟随分 |
| **固定-sigma 网格**（noise-shift 拍板） | holdout 真实图 batch（非采样） | 训练同款 v-pred MSE，但 **sigma 固定**在网格 {0.25,0.5,0.75} 而非随机采 | 各 shift/各消融在同 sigma 下的 MSE（去 confound，可公平比） |

> 固定-sigma eval 是 [model_mot.forward](../networks/model_mot.py) 的小变体（`get_sigmas` 换成固定值），RESULTS.md 明确要求它来拍 noise-shift（exp4 ckpt 已随 /local 清，需重跑小训练或直接在消融 ckpt 上算）。

### 3.4 generate_samples 接入（关键：单卡离线，避开多卡采样 bug）
- **单卡推理**：`run_eval.py` 单进程加载 → 用 [model_mot.generate_samples](../networks/model_mot.py)`(prompts, height=256, width=256, num_steps, guidance_scale, seed)`→pixels。
- **ckpt 加载**：复用 [train.py](../train.py) `load_checkpoint` 的**单进程分支**（`model.model.load_state_dict(trainable_state)`，frozen 塔由 `pretrained_path` 复原）；**config 必须对应该消融版本**（开关一致，否则参数集/指纹对不上）。
- **⚠️ 不要在多卡 FSDP2 训练进程内出图**：交接文档记 `precompute_und_cache`→`forward_und_capture/forward_gen_cached` 在多卡 FSDP2 下有 DTensor 直调遗留 bug。单卡离线 eval 不触发（且 baseline 单卡 KV 缓存已验逐位正确）。B1 adapter 臂采样会 `use_und_cache` 回退 per-step（慢但正确）。
- **EMA 权重**：eval 用 EMA 还是 raw 都试一下（EMA 通常更平滑出图更好）；ckpt 里两者都存了。

### 3.5 验收
1. 对 v1 一个 256 ckpt 跑通：出图 N 张 + 三维度分数 + `results/` 落盘。
2. 四版消融横向对比表（anime 命中/美学/DPG/PRISM/固定sigma-MSE 各一列），能看出差异方向。
3. 固定-sigma MSE 在同 sigma 下可比（验证去除了 confound）。
4. 全程单卡、不影响在跑训练。

### 3.6 依赖与风险
- **官方 benchmark repo**：GenEval/DPG/PRISM 要拉官方（arxiv 被 block，但 github/HF 可用，见坑点#10）。DPG/PRISM 评测器依赖 mPLUG/VQA 模型（几 G，放 /local cache）。
- **PRISM 版本待确认**：有多个同名工作，**先从 [i1 分析](../docs/i1_深度分析与对我们的启发_20260611.md)/消融指南/设计正本找 G7 里"PRISM"的确切依据**再接，别接错。
- **scorer 部署**：tagger-inference/aesthetic-score 是 FastAPI 服务或 pip 包，eval 时起本地服务或 import；权重在 `/fsx/models`（aes-pixai/tagger 已有，见交接文档模型表）。
- **anime evalset 构建**：需 anime tag 体系 + 目标标注，参考 `Concept-Eval/tags_eval/create_evalset.py` 思路 + 我们 anime 源 parquet 的 tags_general/character 字段。

## 0. 结论（TL;DR）

- **决策（Evan 06-19 拍板）：不做 naifu 全迁移**，改走 **方案①「自研补齐」**——给 [train.py](../train.py) 加 **wandb + grad-accum**，以 ~百行级代价拿到 naifu 全迁的主要实际增量。
- naifu 全迁 **搁置而非废弃**：留触发条件见 §5；本文件 §3 的完整 gap 清单是"以后若要全迁"的现成施工图。
- **依据**：naifu 全迁的原始动机是「借它的 dataio」，但 **complete_v1 数据线已自研落地并验好、并已在多版消融上长跑**（截至 06-27 进一步推进，TextAtlas 第 5 域亦已接入）；全迁的最大成本恰是「拆掉已验好的数据线去适配 naifu 的 Rust `dataio`」，而实测 **IO 已 compute-bound**（[RESULTS.md](../experiments/results/RESULTS.md) EXP2，data_frac<0.04）→ dataio 的性能增量 ≈ 0。剩余增量（wandb / grad-accum / 公司栈标准化）用自研补齐即可，无需付数据线重写的代价与回归风险。

## 2. 两边契约速览

| 维度 | naifu `train_fsdp2.py`（鸭子类型、无基类） | 当前 mot_pilot_v1 |
|---|---|---|
| 训练循环 | 框架统一：optimizer/scheduler/grad-clip/**grad-accum**/FSDP2 mesh/DCP+safetensors ckpt/**自动 resume**/**wandb**/validation | 自研 [train.py](../train.py)：**wandb 已自研补齐合入**（§4.1）；尚缺 **grad-accum / eval**（06-27 核验 train.py 仍无）；ckpt = DCP gather + 手写单文件 + **消融指纹校验** |
| model 契约 | `__init__(config)` / `forward(batch)→loss 或 (loss,ts,extras)` / `fully_shard(**kw)` / `generate_samples(...)`；可选 hasattr 钩子（`update_ema`/`ema` 属性/`get_optimizer_param_groups`/`get_training_progress_state`）；可训练塔挂 `self.model` | [model_mot.py](../networks/model_mot.py) **本就照这套契约写**（接口名与注释多处明示对齐 naifu） |
| 数据契约 | **Rust `dataio` 库**：`StoreBase.build_record(row)` + `adapt_batch(batch)` + batch sampler（`__iter__/state_dict/prepare_epoch/offset/current_epoch`）；主循环 `train_fsdp2.py:146` **写死** `dataio.from_sampler + pretrain_data.pipe` | [CompleteV1Dataset](../training/dataline/complete_dataset.py) **不是 torch Dataset、不用 DataLoader**：自建线程生产者 + shuffle buffer + `loader(batch_size)` 生成器，`next()` 取 batch |

| VAE/tokenizer | model 内自带（flux2 同款模式） | model 内自带 ✓ **已一致** |

**关键差异点 = 数据契约**（naifu Rust dataio ↔ 自研线程 loader）。model 契约与混合精度两边已基本一致。

## 3. naifu 全迁完整 gap 清单（存档：以后若要全迁照此施工）

> 按工作量 / 风险排序。file:line 为施工锚点。

### A. model_cls 适配 — 小

| 项 | 现状 → naifu | 锚点 / 备注 |
|---|---|---|
| **EMA 接口** | 自研 `init_ema/update_ema/ema_state_dict/load_ema_state_dict` → naifu `FSDP2EMA`（`self.ema` 属性 + `init_optional_ema` + `update_ema()`→`update_ema_model` + `fully_shard` 里 `self.ema.fully_shard(...)`） | 框架把 `model.ema` 塞进 DCP aux_state，要求实现 `state_dict/load_state_dict`；自研的名字是 `ema_state_dict/load_ema_state_dict` 对不上。最干净=切 naifu `FSDP2EMA`（`networks/ema.py:63`）。自研侧：[model_mot.py](../networks/model_mot.py) `:341-380` |
| **`generate_samples` 签名** | `(prompts,h,w,...)` → naifu hook `(current_epoch, global_step, world_size, rank[, can_write, log_to_wandb])`：rank-strided + PNG 落盘 + wandb log | 当前的当底层、外包一层框架签名。自研侧 [model_mot.py](../networks/model_mot.py) `:382`；naifu 参考 `networks/model_flux2.py:601` |
| **消融指纹校验** | 现在在 [train.py](../train.py) `_ablation_fingerprint_check` (`:92`)；naifu 自动 resume 走 `strict=False`+`allow_partial_load` **会丢这个保护** | **正确性必保留**——迁到 model 的 `get_training_progress_state/load_training_progress_state` 钩子里存指纹+比对，否则坑点#27 的 bidirectional↔causal 静默错续风险回来 |
| `set_train_progress` | naifu forward 不喂 step | 先核实 model 是否真依赖（shift 已不 ramp、读固定常数 `current_shift` [model_mot.py](../networks/model_mot.py) `:262`；可能仅 EMA warmup 用）；依赖则另寻注入点 |
| forward 返回三元组 | `(loss, sigmas, extras)`：naifu `normalize_train_output` 兼容（`torch_utils/train_utils.py:35`），extras 须标量 dict（当前 flow_mse/shift/sigma_mean/img_tokens ✓） | 小：verify per-sample loss + timesteps 形状 |

### B. 数据线适配 — **大（核心障碍）**

naifu 数据流：`sampler 出 row → build_record(row→record) → Rust dataio 取图/decode → adapt_batch(→batch dict)`。
当前 complete_v1 把 **domain_mix / band-first / anime integer-repeat / freq dropout / 在线取图 / caption 构建** 全放在自建 Python 线程里，与 dataio 模型完全不同。两条路都不舒服：

- **真适配**：把整套采样逻辑重写成 naifu batch sampler + 取图改走 `dataio.reader` + caption 放 `build_record/adapt_batch`。数据线是**项目里最复杂、对抗 review 修过 7 个 bug** 的模块 → 重写 = 高回归风险，命中率 / 曝光分布 / 多卡一致性全要重验。**这是全迁不划算的根本原因。**
- **shim 绕过**：写薄 `StoreBase`+sampler 让框架 dataloader 跑起来、实际从自研 loader 取数 —— 但 `train_fsdp2.py:146` **写死** `dataio.from_sampler + pretrain_data.pipe`，绕过得改框架主循环或 monkey-patch（违背"用框架"初衷，脏）。

自研侧锚点：[complete_dataset.py](../training/dataline/complete_dataset.py) `CompleteV1Dataset :202` / `loader :324` / batch dict `:402` = `{prompts, pixels∈[-1,1], cfg_keep}`（**无 latents**，VAE 在 model.forward 在线 encode）；rank 切分在 shard 层 [manifest_index.py](../training/dataline/manifest_index.py) `:97`。

### C. config 适配 — 中

当前 schema `model/vae/dataset/sigma_sampling/optimizer/scheduler/trainer` → naifu 顶层 `model_cls/sampler_cls/ckpt_path/hsdp_partition_size` + `net/trainer/dataset/optimizer/scheduler/sampling/validation` 段。
model 读自己的 `config.model.*`/`config.sigma_sampling.*` **可保留**（naifu 不强制 `net` 命名），主要是补框架读的键 + `trainer` 段改名（`checkpoint_dir/safetensors_dir/checkpoint_steps/keep_last_n/use_wandb/accumulate_grad_batches/gradient_clip_val`…）。

### D. 正确性验证 — 必做（Evan 偏好）

迁移后：loss 与当前 train.py **同 seed/同数据逐步对齐**（bf16 容差内）；EMA/ckpt/resume round-trip；消融指纹仍生效；若动数据线，batch 域占比/曝光分布与自研一致。

**白得的（框架免费）**：grad-accum、wandb、safetensors 导出（可 `s3://`）、loss-vs-timestep 分桶、validation loop。

## 4. 选定方案①：自研补齐（本次执行计划）

> 原则：**不动数据线、不动 model_mot 核心、不引入 naifu 依赖、不改 ckpt 格式（保留消融指纹）、不打断在跑的 4 个消融 run。** 仅在 [train.py](../train.py) + config 上做加法。

### 4.1 wandb 接入
- **现状**：[train.py](../train.py) `:304` 写 `metrics.jsonl` + stdout，无 wandb。
- **改**（抄 naifu `train_fsdp2.py:341 init_wandb` 的做法）：
  - rank0 且 `config.trainer.use_wandb=true` 才 init；其余 rank 与关闭时无副作用。
  - 每 step log：`total_loss / grad_norm / lr / iter_time / peak_mem` + forward extras（`flow_mse/shift/sigma_mean/img_tokens`）。
  - **run_id 持久化**到 `checkpoint_dir/wandb_run_id.txt`，resume 时 `resume="allow"` 续**同一** run（不新建）。
  - **保留 `metrics.jsonl` 双写**（离线可查、不依赖外网）。
- **config**：`trainer` 段加 `use_wandb / wandb_project / run_name / wandb_entity`。
- **依赖**：venv-gpu 需装 `wandb`（开工前确认是否已装）。
- **⚠️ 开工前先验证的 open question**：集群能否连 wandb 外网（参考坑点#10 arxiv 被 block）。若不通 → 走 `WANDB_MODE=offline` + 事后 `wandb sync`，或仅离线。**这点不明，执行前先 AskUserQuestion / 实测一次。**
- **验收**：rank0 起 run 并上报；resume 续同一 run；非 rank0 不写；关闭时退回 metrics.jsonl 行为不变。

**✅ 已实现、CPU 验证、并已合入 `main`（实现 2026-06-19；合入确认 2026-06-27）**：
- **合入状态（2026-06-27 核验）**：`wandb-integration` 分支已 merge 进 `main`（git `ae1ccc0 Merge branch 'wandb-integration'`，实现 commit `8efdb77`）；当前 `train.py` 内 `WandbLogger` 已在主干（`:70` 类定义、`:248` init、`:370` 每步 log、`:399` finish）。原"待安全窗口"已完成。
- 实现 = `WandbLogger` 类（rank0-only + `use_wandb` 门控 + import 容错 + **在线优先、连不上 api.wandb.ai 自动退 offline** + run_id 持久化 resume 续 run + 任何 wandb 故障降级 no-op 绝不中断训练）+ 3 接入点（init / 每步 log / finish）；config `trainer` 段加 `use_wandb`(默认 false)/`wandb_project`/`wandb_entity`/`run_name`/`wandb_mode`。改动**纯加法**。
- CPU 验证全过：① 基线 `use_wandb=false` 行为不变（无 wandb 目录、metrics.jsonl 正常）；② offline 端到端（指标带 `train/` 前缀上报、`wandb_run_id.txt` 生成、metrics.jsonl 双写）；③ resume 续**同一** run id（`zwb3qt5p`=`zwb3qt5p`，metrics 12+12=24 行）；④ reachable 探测 api.wandb.ai=True / 不可路由地址=False（fallback 判断正确）。
- **启用方式**：venv-gpu 已装 wandb 0.27.2（纯新增、未动 torch/transformers/numpy）；新 run 的 config `trainer` 加那几行 + `use_wandb: true` 即可（默认 false → 不开则行为完全不变）。
- **Evan 用前一次性**：能联网的机器 `wandb login`（或设 `WANDB_API_KEY`）；用个人号 → `wandb_entity` 留空即可（用默认 entity）。
- **JCC 节点注意**：训练在 JCC H100 跑、其外网连通性未知；代码 init 时自动探测，连不上**自动退 offline**（wandb 文件写 `checkpoint_dir`，事后在能联网机器 `wandb sync <目录>` 补传）。本机 CPU 节点实测可达，但不等价 JCC。

### 4.2 grad-accum
- **状态（2026-06-27 核验）：尚未实现**——`train.py` 内仍无 accum 逻辑（grep `accum`/`micro` 无命中）。下文为待执行计划。
- **现状**：[train.py](../train.py) 每 step 一次 forward/backward/step，**无累积**。
- **改**（抄 naifu `train_fsdp2.py:213/640` 做法）：
  - 加 `config.trainer.accumulate_grad_batches`；循环累积 N 个 micro-batch 再 `optimizer.step()`。
  - FSDP2 下非 step 边界用 `model.model.set_requires_gradient_sync(False)` 关梯度同步省通信。
  - loss 除以 N；**scheduler / EMA update / ckpt 计数 / global_step 全按 optimizer-step**（非 micro-step）。
- **⚠️ 语义点**：引入 accum 后必须把 `global_step` 明确为 **optimizer-step**，否则步数/采样口径乱（关联 [当前进展_交接GPU.md](../当前进展_交接GPU.md) §8 fixed_steps/fixed_samples 的换算）。
- **价值诚实标注**：当前 256 已 bs64 / 512 bs32 从容（[RESULTS.md](../experiments/results/RESULTS.md) / 交接文档 §3 G2 表），**未必是瓶颈**；主要给 1024 或更大模型 / 想抬有效 batch 时留路。属"框架白得就补上"，非急需。
- **验收**：`accum=1` 与现在**逐位等价**（回归）；`accum=N` 的 loss/grad 与 `batch×N` 单步数值接近；显存不随 N 线性涨（梯度不累显存，激活按 micro-batch）；多卡通信只在 step 边界。

### 4.3 不做什么（边界）
不动 [training/dataline/](../training/dataline/)、不动 [model_mot.py](../networks/model_mot.py) 核心 forward/采样、不引入 `dataio`/naifu 任何 import、不改 ckpt 单文件格式与消融指纹、不碰正在跑的 4 个消融 run 的代码/config（坑点#11：提交后冻结代码）。

## 5. 重启「全迁」评估的触发条件

出现下列任一，回头重看 §3 全迁清单：
1. 需要团队共享 naifu 实验看板 / 用 naifu 复现协作。
2. 要用 naifu **专有 dataio 特性**（某种 bucketing / 缓存 / 多源 join）且自研补不动。
3. 公司要求统一训练栈。
4. 数据线本身要**大改**（届时"在 naifu 上重写"可能比"改自研"更划算，顺势全迁）。
5. 要复用 naifu 的 validation / safetensors-to-s3 / 蒸馏等成套设施且自研补成本反超全迁。

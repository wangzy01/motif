## 2. 两个参考的关键启发（i1 + minit2i，原文+代码已核）

### i1（zlab-princeton，3B 纯 T2I，dual-stream MMDiT + T5Gemma-2B 冻结 encoder + FLUX.2 VAE）
- **分辨率课程（实测 config）**：256=2M步 / 512=+0.5M步 / 1024=+0.3M步（cumulative total_steps 2M/2.5M/2.8M，从上一阶段 resume）；batch 512/512/128。**前置重投 256**（占算力大头），高分辨率短。
- **256 "~500K 就 stabilize、2M 才完全收敛"**；**512 是涨分主力**（PRISM/LongText 0.75→0.92）；**1024 增益小**（"stays close to 512 ckpt"）。**512 高分辨率不需广覆盖**（只用 real 或只用 synth 都能拿到相当的 LongText 提升；池 9.7M 重复~26ep / 1024 池 4.3M ~9ep）。
- **数据全等权**（每数据集 ~1/11），cap@1.2M=等权最优，单源上采样×3/×5 都不赢等权，**删最差源(iNaturalist)是纯增益**。**重复便宜**（D5：每源砍到 0.4M unique 重复几十遍只掉一点）。
- **caption 长度（关键表 tab7）**：训练 100%长 + 推理改写 = 0.73(最好)，但 100%长 + 原始短prompt = **0.17(崩)**；20%长 = 短0.47/改写0.67(两端都稳)。**"训练与推理 prompt 长度必须对齐"**。**i1/minit2i token 预算都是 256**。i1 推理用**现成 Qwen3-4B 改写**(零训练改写器)；多 caption/图(5条长synth)。
- **noise-shift（实测 config 表）**：256=N/A、**512=N/A(不shift)**、**1024=3.33**(只 1024 shift，且做过 shift-vs-noshift 消融确认有益)。**lr 1e-4 const、无 warmup、wd=0、EMA0.9999、grad-clip1、Adam(0.9,0.95)。**
- **架构**：text adapter(2 transformer blocks，"加大adapter≈多接encoder")、去AdaLN、long skip、sandwich norm。我们的 B1 adapter / ab2fusion 与此一致 → 继续投 adapter 是对的。
- **不可迁移**：100%长caption(需强制改写)、textatlas 高权重(文字渲染是 i1 的目标、非我们的)、全域等权(我们要 anime 重)、CFG12 应试调参、绝对步数(我们暖启)。

### minit2i（258-912M 像素空间，单 512 分辨率）
- **能力→对齐两段结构**：pretrain(CC12M 长recap，250K步，覆盖) → **alignment finetune(120K 高质量 synthetic 混合，40K步，"教好答案"=类似 LLM SFT)**。**混合两池会两头稀释、必须分开成阶段。** 对齐段显著降生成多样性(caveat)。
- caption 256-token 预算。文字渲染建议掺进 **alignment 段**一小片(非 pretrain)。试过 Qwen3-VL-2B 当 encoder 觉得不值(小模型)。
- **对我们最大启发**：课程末尾需要一个"小而精、高质量"的集中阶段教"好答案"——这正是新计划末尾的 anime 精选收尾段。

- **Q4 multi-AR = 512a 开始加，前 10-20% square warmup 再开 AR 桶**。架构已支持非方图（MRoPE），零模型改动；分桶 sampler 参考 TUNA-2、桶表参考 Hunyuan ResolutionGroup（等面积 262k、每边整除 16）、rank 一致。

- **a = real 维持 rich_v1 60M 全量**（GPIC 留在池里，单调靠类别权重压，不扩 GPIC）。
- **b = 轻手类别软封顶**（不激进清洗；real 只是 grounding、照片有用、别过度工程，对齐 i1/minit2i 极简哲学）。

- **（2026-06-29）M9 修法 = rich_nl 改 refined 优先**（取最长 NL；现 medium 优先是 bug）。token 预算保持 384，属"修 M9+对齐 proxy 后**重测确认**"的待验证项（非决策）。
- **（2026-06-29）512b multi-caption 护栏 = 只靠现有随机变体（免费、不生成）**：anime route 随机抽 + tag dropout/length-cap/anchor 随机（同图跨 epoch 几乎不重复同一 caption）+ MONET 5 captioner 轮换。**不**用 Qwen3-VL-30B 生成新 caption；若之后出现记忆再补（loader 可预留接口）。
- **（2026-06-29）⑥ token 预算 = 分阶段：stage256=384 / stage512a/512b=512（1024 同理 512）**（Evan 先选全程 384、后**收回改为升 512**，最终落到数据支持的分阶段档）。今日真-tokenizer audit（`experiments/results/token_trunc_audit_20260629_anime_only/`）实测：@384 干净尾截 256=16.1%/512=12.6%（`post model over=0` 非 mid-token）、@512≈0%。token 经济学：256 处 text 主导（256 img tok、+128 text=~33% 算力）→保 384 省算力且 16% 干净尾截可接受（345 budget 已 >i1/minit2i 的 256）；512+ image 主导（升 512 仅 +~9%/可忽略）→升 512 把截断打到 ~0、dense-NL 全保真。M9 修法（refined>medium）不变（rich_nl 本就是 dense 路由）。⚠️ 我早前"13.85% 大半伪截断、修后压 1-2%"的判断被实测推翻——是真截断。`model_text_max_length` 需做成 per-stage（架构/frozen Qwen3-VL encoder + adapter 支持变长，可行）。
- **（2026-06-29）⑧ 阶段切换 = 继承 optimizer + 换分辨率小 warmup**：继承 Adam moment + const LR；仅在**换分辨率**时（256→512a、512b→1024）加几百步 re-warmup（latent token 数变、loss 景观移）；**同分辨率内（512a→512b 只换 mix/池）直接续**。比 i1（全程无 warmup）多一道换分辨率小 warmup 保险。
- **（2026-06-29）⑨ config 统一 = canonical global batch 512 @ lr 1e-4（对齐 i1）**：曝光量驱动（steps=exposure/batch）；实际 batch 随硬件扩、LR 按 sqrt 缩放（512→1e-4 / 1536→1.73e-4，现 v2 已是）。

### 6.5 photo vs 非photo（JCC job `evan-mot-photo-binary-5dmb`，5.98M 候选池图）

## 数据源与角色

- **MONET real**（筛后约 77M @256 / 59M @512）：主力底子。
- **MONET synthetic**（13.8M，全 1024px）：保留并打 `synthetic` 标记；既补合成图带来的能力，也是 **1024 阶段的主要高清来源**。
- **GPIC**（采样约 20M）：**本质是 256 资产**，补 256 真实摄影的多样性 + 干净的短/中 caption。
- **TextAtlas**（5.4M，新增、低优先）：补"能写字"的基础能力，英文写实文字为主。
- **anime**（16M，团队已处理好）：最终目标域。

## 一、筛选规则

### MONET（只用已有元数据，不额外计算）

按顺序：

1. **基础质量**：短边 ≥256、宽高比 ≤3、白色像素 <95%。
2. **美学地板**：cc12m / commoncatalog-cc-by / megalith10m 用 `aesthetic_jasperai ≥ 5.0`；laion / coyo / da4k 不加。
3. **水印**：每个来源删 `wk_jasperai` 最高的 2%（约阈值 0.30），原始分数保留。
4. **敏感内容**：默认不处理，仅删任一 nsfw ≥0.9 保险。
5. **分辨率标记**：短边 ≥512 可用于 256/512 两个桶；短边在 [256,512) 只用于 256。
6. **合成图**：只做基础质量过滤（不过美学），标 `synthetic=1`。
7. **子源配比**（新增）：MONET 由 9 个子源拼成，laion(45M)+coyo(19M) 占了 real 八成；采样时对大子源设上限（cap），防单一爬虫源垄断，具体阈值等联合聚类结果出来再定。不做"删最差源"。

实测保留量：real ≈ **77.0M**（短边≥256）/ **59.4M**（短边≥512）；synthetic 13.8M（全 1024px）。

### GPIC（GPU 补算特征后筛）

1. **基础过滤**：排除 test/val，短边 ≥256、宽高比 ≤3（约 99M）。
2. **跨源去重**：与 MONET 的 SSCD 相似度 ≥0.75 命中，删 GPIC 侧（MONET 元数据更全、优先保留）。
3. **美学过滤**：按 `aesthetic_laion-improved` 删最低 **10%**。
4. **分层采样到约 20M**：按内容聚类 × 分辨率分层，同层内美学优先。

**定位（重要）**：GPIC 中位短边只有约 427，短边 ≥512 的仅约 5%、≥1024 基本没有。所以 GPIC **默认只进 256 阶段**；512+ 退场，只把"短边≥512 且高美学"的小子集留作 512 阶段的多样性补充/消融，**不上采样、不进 1024**。

### TextAtlas（新增，低优先）

- **用途**：低优先补"文字渲染"的基础能力（英文写实海报/PPT/书封）。不追该方向 SOTA；二次元/日文文字它帮不上，后续另议。
- **量 / 分辨率**：总 5.4M；短边 ≥512 约 4.0M；≥1024 约 0.9M。
- **caption**：直接复用 i1 开源的长 caption（`caption1-5`，每图最多 5 条，训练时随机取一条）。GT 文本只存为辅助字段（如 `text_gt`），**不当训练 caption**，避免模型"看到文字串就硬画字"。
- manifest 保留 `textatlas_subset`（10 个子集），便于后续按副作用对子集调权。
- **跨源去重**：与 MONET(laion/coyo)/GPIC 做 SSCD 去重（海报/书封容易和网图撞图），留一时文字图保 TextAtlas、写实图保 MONET。

### 最终数量控制

合并后 real 目标 60-80M（MONET 为主 + GPIC ~20M）。超 80M 优先减 GPIC，再把三源美学阈值 5.0→5.25；低于 60M 放宽到 4.75（基本不会发生）。

## 二、采样配比（设计意图；实际数值见 AAA §11.5 + config）

> 本节是**为什么这样配**的设计意图（pilot 起点、可调）。各 stage 的**实际 domain_mix 数值已搬到** [AAA数据交付文档 §11.5](AAA数据交付文档_GPIC+MONET+anime_v2_20260617.md) + `configs/t5_sampling_complete_v1.json`（生产正本，5 域含 textatlas）；本文不再复列以免双源漂移。下面只留课程级取向：

- **大盘**：real:anime ≈ 4:1（沿用）；synthetic / TextAtlas 从 real 预算里挤一小块、不抬高总量，故真·real(含 GPIC):anime 实际 ≈ **3.5:1**（略偏 anime，符合二次元目标，已采纳）。各阶段受分辨率门影响、构成自然变化。
- **256**（数据最多）：anime 低、MONET-real 主力 + GPIC 补真实摄影多样性 + synthetic/TextAtlas 低权。real 内 MONET:GPIC 设计原写 80:20，**complete_v1 已改为 11:7**（= 静态池 11M:7M 自然比，让 GPIC 按真实池占比进 256；见 AAA §11.5 / 采样权重 spec §6）。
- **512**：anime 抬到 ~50-65%（real:anime ≈ 1:1~1:2）；MONET-real 主导其余 real，TextAtlas 在这一档文字变清晰、可加。（设计原写 GPIC 退场；complete_v1 后又把 GPIC 加回 512 补真图量，以 config 为准。）
- **1024+**：anime 主导；real 防遗忘主要靠 synthetic（高清来源，13.8M 全 1024px）+ MONET-real 短边≥1024（约 8-9M，主要 commoncatalog）；GPIC 为零（无 ≥1024px 图）。

> 补充（设计依据）：MONET:GPIC 自然可用量其实约 44:56，主动把 GPIC 采到 ~20M、不放它垄断，是因为它分辨率低、美学低、摄影同质。

## 三、Caption 方案

按 token 分四档（Qwen3 tokenizer）：T1 ≤24 / T2 25-64 / T3 65-128 / T4 ≥129。这里"长"指详细描述段落（约 T3+T4）。

1. **real 域配比**（pilot 起点、可调）：T1 18 / T2 27 / T3 15 / T4 40。
   - 即详细档(T3+T4) ≈ 55%，其中真长 T4 ≈ 40%（多用 gemini 全段落）；tag/真短 T1 ≈ 18%（兜真实用户的裸短 prompt）。
   - 相对原案 10:30:40:20 的变化：真长 T4 由 20→40、tag/短 T1 由 10→18；详细档总量基本维持（原本就约 60%）。
   - 供给充足：MONET real 约 99% 有 sharegpt4v、约 90% 有 gemini，**不需要重新 caption**。
2. **长档截断**：约 **224-256 token**（按句子边界截）。不要截到 150——gemini 中位就有 179 token，截 150 会把过半长 caption 腰斩。（2026-06-18 已上调至 ~300-340 proxy / 真 token budget 343，见实现现状指南）
3. **anime**：沿用团队现有体系（Stage1 NL长/NL短/hybrid/tag = 50/20/20/10；Stage2 抬 tag + 按词频做 tag dropout）。
4. **synthetic**：只有生成 prompt（中等长度），天然落中档。
5. **TextAtlas**：训练只用其长 caption（见上）。
6. **T1 短档来源**：MONET `caption_original` 是网页 alt-text（噪声大、不是干净 tag），有意保留以提升对真实短 prompt 的鲁棒；干净 tag 主要来自 GPIC（约 1%）。
7. **特殊处理**：megalith 的 T2 用 florence 首句（≤64 token）；ccc / megalith 无 T1，采到时回退；internvl 删末尾不完整句子。
8. **dropout**：全程 10% caption dropout（沿用）。但 **TextAtlas / 含文字样本单独处理**——调低甚至关掉其 dropout，或 dropout 时挂一个"含文字海报域"标签，避免"空 caption → 含字图"被学成"无条件出字"。
9. **推理改写**：不作为依赖。模型自带冻结 Qwen3-VL，可选挂一个"短→长"自改写开关，默认关、不进评测主指标。
10. **manifest 字段**：每个 caption 字段存 token 数和所属档位；全量统计可用"词数 × 1.32"近似（误差 <2%）。
11. （可选、v1 不做：用 `classifier_clip` / `detection_yolo` 的标签拼 tag caption。）

## 四、文字数据副作用监控（加 TextAtlas 后必做）

固定一组"无文字意图"的 anime/tag + 通用 prompt，定期采样，监控：① 普通 prompt 是否无故出现文字；② 是否多出签名 / 水印 / 用户名；③ 是否出现海报 / 居中标题 / 大留白的版式漂移（按长宽比分桶看——海报多是非方图，可能集中在少数桶，必要时对这些桶单独限 TextAtlas 占比）。出问题就调低 TextAtlas 占比甚至置 0，或推迟到 512 才加入。

## 五、其他沿用原则

- western / person 偏置**只标记、不硬删**：靠联合聚类标签 + 采样权重后续控制比例，避免提前破坏多样性。
- 中等相似样本（SSCD 0.6-0.75）暂不直接删，留到聚类阶段做簇内留一。
- 只下采样，**不把低分图上采样当高清**。

## TODO（处理流程）

1. GPIC 全量特征补算（SSCD disc_mixup、CLIP-B/32、aesthetic_laion-improved、pHash）。
2. MONET 全量筛选 + 样本清单生成（CPU 为主，可与上并行）。
3. 跨源去重：MONET ↔ GPIC（高相似删 GPIC 侧）；**新增 TextAtlas ↔ MONET(laion/coyo)/GPIC**（建 manifest 时顺手做）；MONET 内部高相似做簇内留一。
4. MONET × GPIC 联合聚类 + 粗内容标签（控制人物/产品/文字/插画等比例，并作为子源 cap 的依据）。
5. **TextAtlas 下载入 S3 + 建 manifest**（含分辨率/AR 分布、`textatlas_subset` 标签、复用 i1 caption）。
6. GPIC 分层采样到 ~20M + 合并 MONET 交付（总量控制 60-80M）。

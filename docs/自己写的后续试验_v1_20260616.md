## RAEv2-on-Qwen3VL-ViT 统一潜空间（VAE→RAE）

把原版生成路径的 VAE 换成 RAE：生成 latent = 冻结 Qwen3-VL ViT 的 pre-merger patch 特征，只训 decoder 解回像素；扩散在该语义 latent 内做。

**可行性调研**

- **代码分析**：RAEv2 decoder = HF ViT-MAE decoder，编码器冻结、只训 decoder；noise-shift / x-pred / 多层 sum 都在 `nanovisionx/RAEv2`、`ZitengWangNYU/Scale-RAE`。diffusers v0.38 有 `AutoencoderRAE`（仅 dinov2/siglip2/mae）→ 对照组可直接用；Qwen3-VL 需自写 encoder wrapper。

**怎么做**

- **pre-merger 读出**：512px·patch16 → 32×32×1024（等效 f16、token 友好；通道 1024 偏重）。务必 pre-merger（merger 后 2×2 只喂 LLM）。
- **三处改动**：① `proj_in=Conv2d(1024→2048, kernel=1)`，不再 2×2 patchify；② per-channel 归一化（`compute_encoder_stats.py`）；③ noise-shift 必须扫 3/5/8/16——公式在 512px 给出起点 ≈16，但太激进、不当默认，按 loss/样本/细节定（命门：Scale-RAE 开/关 = GenEval 49.6 vs 23.6）。2–4B 宽度 > 潜维 1024，省 wide-DDT 头。
- **多层 sum**（#9）：A/B Q-K1(final) / Q-K7(last-7) / Q-Deep([5,11,17]+final)。
- **decoder 损失**：Scale-RAE 式 ℓ1+LPIPS+Gram+对抗（anime 细节可能需要）。

**先只训解码器看重建效果（先不动 UMM）**

对照：看训解码器的成本。有时间可与普通 VAE（FLUX/Qwen-Image）、官方 SigLIP2 做的 RAEv2 对照（主要判断"Qwen 为识字/理解而做的训练是否伤了重建"）。

## E0–E9 实验清单

- **E0 · VAE 基线** — 目的：所有 RAE/RAC 结论的对照尺。怎么做：现成 VAE（FLUX 或 Qwen-Image v1）+ 我们的生成分支，照常训一版 T2I。要考虑：与 E2 完全对齐（参数/数据/步数/分辨率/eval prompts）否则无法公平比。判据：固定 eval 集 GenEval/DPG + 主观。

- **E1 · RAE 解码器 bake-off（闸门）** ［RAEv2 `2605.18324` / Scale-RAE `2601.16208`］ — 目的：回答"Qwen3-VL 的 ViT 特征能不能解码回清晰图"。怎么做：冻结 ViT，取 pre-merger patch 特征当 latent，只训一个 ViT-MAE 式解码器（ℓ1+LPIPS+对抗），并在该 latent 上训个小 DiT 做 probe 测可扩散性。要考虑：①取哪几层（只末层 / 末 7 层 / Qwen 的 5·11·17+末层 三组）②per-channel 归一化先算好 ③先固定 512 分辨率 ④对照官方 SigLIP2/DINOv3 RAE（diffusers `AutoencoderRAE` 可直接用）+ 普通 VAE ⑤评测集必须含大量细节/文字 ⑥解码器喂含文字数据（text-rFID 可再降约 40%）。判据/闸门：细节/文字图重建 rFID 进 VAE ~2× 内，且小 probe 不明显弱于 VAE → 过；否则退 VAE 或上 E5。
  > ⚠️ **此条与 [E1_RAE 解码器 bakeoff 实施 spec](E1_RAE解码器bakeoff实施spec_v1_20260624.md)（另一 agent 负责的正式 spec）直接重叠**——以那份 spec 为准，本条仅作历史想法记录。

- **E2 · 最小 RAE 接入（核心）** ［RAEv2 `2605.18324` / Scale-RAE `2601.16208`］ — 目的：坐实"换 RAE ≥ VAE 且更快收敛"。怎么做：生成分支 VAE→RAE latent，只改 3 处：1×1 卷积投影到模型宽度、per-channel 归一化、noise-shift（按公式 α=√(m/n)、n=4096 算出，在算出值附近轻量 sanity）。RAEv2 默认件全开：x-pred 自引导 + self-REPA（不再做有/无对比）。要考虑：只动 tokenizer 一个变量；解码器冻结、可离线 eval。判据：GenEval/DPG ≥ E0 且收敛更快。

- **E3 · 纠偏解码（RAC）🆕** ［RAC `2603.05925` ⚠️[待核实] / RAEv2 `2605.18324`］ — 目的：解决 E2 最大风险——生成器吐出的 latent 偏离编码器流形 → 一次性解码就崩（生成-重建 gap）。**注意：RAC 只开源了 demo。** 怎么做（由轻到重，做一档评一档）：
  1. **Latent-RAC（先做）**：在 RAE latent 空间训一个 rectified-flow 小模块，把"生成出的 z_hat"用 1–4 步拉回真实编码器流形（z_hat→z*），再用普通 RAE 解码器解码。
  2. **RAC 多步解码器**：把一次性 RAE 解码器换成 RAC 的 2/4/8 步可纠偏解码器（同一模型时间反演还能当编码器）。
  3. **RAC path-consistency 损失**：约束生成路径更直、更可解码（可并进 E2 训练）。
  4. **[兜底] 像素级 refiner（DeCo/SDXL 式）**：若 latent 纠偏后细节仍不够，再在解码预览图上补高频。
  - 要考虑：训练样本必须含真实"生成 latent"（generated-latent mining：拿当前 T2I checkpoint 采样的 z_hat 来训纠偏），不能只用合成噪声 corruption，否则只提升重建、缩不了真实 gap；别过度平滑（尤其细线/高频）；多步会加 NFE（先用 Latent-RAC 1–4 步控成本）；RAE latent 是 768/1024 通道 patch 特征、不是低通道 dense latent，RAC 原版"全分辨率 state"要重设计、别照搬（会爆显存）；不要用 RAC 的 reverse encoder 替代 RAEv2 编码器（丢语义）。RAC 证据是 ImageNet-256/SiT、未在 RAE/大规模 T2I 验证 → 属研究性。判据：同一批生成 latent 的解码质量（artifact 率/线条/文字）明显改善，且不过度平滑、推理成本可接受。

- **E4 · FreqWarm 频率课程（可选）** ［FreqWarm `2511.22249` ⚠️[待核实 2026-06-27: 序号偏高，引用疑似未核实]］ — 目的：救"高维 latent 收敛慢/高频弱"。怎么做：训练早期多暴露高频信号（即插，不改架构）。要考虑：仅 E2 收敛慢或高频偏弱时才加（高维 VAE 上报告 gFID −14 量级）。判据：gFID/细节改善否，无则不留。

- **E5 · 混合 latent（RAC 不够时的更重备选）** ［SFD `2512.04926` ⚠️[待核实] / ReDi `2504.16064` / Prism `2512.19693` ⚠️[待核实]］ — 目的：E3 RAC 仍救不回细节时的"一体化"方案。怎么做：主体走 RAE 语义 latent，另开一条很轻的像素残差通道（浅层 VAE 残差解码器），像素级残差相加，只训残差支。要考虑：两支梯度平衡（频带分离损失约束残差支只学高频）；比 RAC 更重，故排在 RAC 之后。判据：细节达标且语义/构图不退。

- **E6 · RecA 后训练（收尾可选）** ［RecA `2509.07295`］ — 目的：便宜的后训练提分（自监督自重建）。怎么做：后训练让模型用自身 Qwen3-VL 理解特征当条件重建图。要考虑：盯多样性/prompt-following 别降；放最末做一次消融。判据：GenEval/对齐提升且多样性不退。

- **E7 · 纯 pixel 对照** ［SenseNova-U1 `2605.12500` ⚠️[待核实] / Tuna-2 `2604.24763` ⚠️[待核实] / HiDream-O1 `2605.11061` ⚠️[待核实]］ — 目的：给"latent vs 像素"研究对照结论（不追它赢）。怎么做：同骨架去掉 VAE/RAE，直接像素 patch 生成；同等数据/参数/步数对比。要考虑：我们规模下大概率更难更慢（Tuna-2 优势在 550M 对/7B 才显现）；价值在结论。

- **E8 · VAE+RF 机制验证（RF，靠后）** ［RF `2605.31604` ⚠️[待核实 2026-06-27: 与省流"6 月"不符、序号偏高，引用疑似有误]］ — 目的：不碰 RAE 前提下单独验证"先预测结构 token 再生成"是否值得。怎么做：普通 VAE 基线上加 RF，先 AR 预测离散结构 token 再生成；复现 RF 0.52→0.77。要考虑：在线 VQ 码本(8K/16K)+Sinkhorn/EMA 防塌；推理多一段；只在 VAE 上验机制，不接 RAE。判据：构图/组合性是否真提升、代价可接受。

- **E9 · RAE+RF（最后）** ［RF `2605.31604` ⚠️[待核实]］ — 目的：仅当 E8 证明 RF 有价值，才考虑接 RAE。要考虑：RAE 已语义 → RF 大概率冗余；离散化伤细节 → 风险高。排最末，不做也行。

## 推进顺序（哪些并行 / 哪些有依赖）

- **第 0 步 · 现在并行起跑（互不依赖）**：E0 VAE 基线 ‖ E1 RAE bake-off（内部取层对比 / tokenizer 对照 / 小生成 probe 也并行）。独立支线 E7 有空闲算力随时可起。
  - → **闸门**：E1 重建（含细节/文字）+ 小生成 probe 过线 → 进 E2；不过 → 走 E5（混合 latent）兜底，或退回 E0 的 VAE。
- **第 1 步 · 核心里程碑（串行）**：E2 最小 RAE 接入（只动 tokenizer 一个变量，RAEv2 默认件全开）。确认"换 RAE 后文生图 ≥ VAE 且收敛更快"——主创新结论。
- **第 2 步 · 按需加（E2 后，一次只加一个变量）**：
  - **E3 纠偏解码(RAC)** —— E2 一旦暴露"生成-重建 gap"（生成图明显差于重建图），这是首选加法；内部由轻到重（Latent-RAC → RAC 解码器 → path-consistency → 像素 refiner 兜底）。
  - **E4 FreqWarm**（仅收敛不佳时）、**E6 RecA**（收尾）并行。
  - **E5 混合 latent** —— 仅当 E3 RAC 仍救不回细节时再上（更重、要平衡两支梯度）。
- **最后才碰 RF**：E8 VAE+RF（先在 VAE 上验证机制）→ 只有它证明有价值，才考虑 E9 RAE+RF（冗余/伤细节风险）。

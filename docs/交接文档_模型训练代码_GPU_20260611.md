## 3. 决策记录

**用户已拍板（2026-06-11，不要重新讨论）：**
1. 训练入口 = 独立精简 train.py（naifu 契约对齐；正式训练首选把 networks/ 搬进 naifu 用 train_fsdp2.py）；
2. 文本条件 = Qwen-Image 式 chat template（`prompt_template.enabled` 可关，默认开）；
3. σ 采样 = logit-normal + shift（uniform 已实现可切）；
4. Qwen3-VL-2B 已下载；FLUX.2 VAE 权重暂不下（等 VAE gate）。

**上一棒的默认选择（用户知情，遇到相关实验先问用户要不要改）：**
- shift ramp 终点 = 50% 训练进度（方案只说前 5% shift=1 → ramp 到 3，没定终点）；
- `timestep_multiplier=1000`（diffusers 刻度；Cosmos3 的 timestep_scale=0.001 等价于 multiplier=1，值得扫 {1,10,1000}）；
- 模板 token 对噪声图可见（MoT 无 Qwen-Image 的 drop-prefix 步骤）；
- proj_out（v-head）零初始化；
- patchify 2×2（patch_dim = VAE 通道 ×4）；text_max_length=256（模板 39 token + caption 长档 ~150）。

## 5. 建议的 GPU 任务清单（动手前先用 AskUserQuestion 和用户对齐范围！）

按依赖序，每项给验收标准。G1-G3 是显然要做的；G4 起范围未和用户确认过。

**G1 · GPU 环境/真权重 smoke（最先）**
- `nvidia-smi` 确认卡；venv-gpu 在 GPU 机上 `torch.cuda.is_available()` 应为 True（cu128 venv vs 机器 driver/cuda 版本若不兼容，参考 T1-T5 v2 接力文档 §5 的 fallback 思路）。
- 跑 `scripts/smoke_real_weights.py`（先 CPU 语义，再加 `--skip-hf-ref` 提速重复跑）。
- 验收：5 项检查全过（同 §2 表）。

**G2 · 单卡真规模训练 step（bf16）**
- 真 2B 权重 + stub 数据 + FakeVAE(c128/f16) + 512px 等效 latent，单卡若干百 step。
- 现状提醒：模型默认 fp32；GPU 上需要 bf16 路线（建议 autocast 或 model.to(bf16)+loss fp32，**loss 计算已显式 .float()**）。train.py 还没有 autocast 开关——需要小改，改完记得同步 README。
- 序列很短（256 text + 256 img = 512），单 H100 富余很大；显存参考：权重 bf16 ~6.3GB + AdamW fp32 states ~11GB。
- 验收：loss 有限且对 overfit_one 单 batch 明显下降；吞吐/显存数字记下来报给用户。

**G3 · SDPA mask 路径的 GPU 正确性 + 吞吐**
- 我们用 bool attn_mask 的 SDPA（FlashAttention 不吃任意 mask，会走 efficient/math backend）。在 GPU 上验证：① 不报错不静默退化（看 `torch.backends.cuda.sdp_kernel` 日志/ profile）；② 测吞吐，若太慢，候选方案 flex_attention 或 packed+FA varlen（Cosmos3 做法），**先报数字给用户再动**。
- 验收：单卡 step 时间、SDPA backend 名称、显存峰值三个数。

**G4 · FSDP2 2 卡验证（`model_mot.fully_shard` 从未跑过）**
- train.py 目前是单进程；要么补 torchrun+FSDP2 初始化（参考 naifu train_fsdp2.py 的 setup_parallelism/MixedPrecisionPolicy），要么直接开始把 networks/ 搬进 naifu（正式路线，框架结论文档支持）。**两条路线选哪条先问用户。**
- 验收：2 卡 loss 与单卡同 seed 量级一致、checkpoint 能存能续。

**G5 ·（范围外，用户点头才做）** 采样器（Euler + 双前向 CFG + frozen und 路逐层 KV 缓存）、真 VAE adapter（等 VAE gate 拍板）、数据管线接入（等 T1-T5 manifest）。

## 6. 工程坑（直接抄走，都是踩过的）

1. **HF 加载陷阱**：`Qwen3VLTextModel.from_pretrained(全量checkpoint)` 会因 `model.language_model.*` 前缀全部 MISSING **静默拿到随机权重**。要参考输出必须 `Qwen3VLForConditionalGeneration.from_pretrained(...).model.language_model`（smoke 脚本里已修正并有注释）。
2. transformers 必须 ≥4.57 才有 qwen3_vl；`/opt/venv`（4.56）不行，用 venv-gpu（5.11.0）。
3. venv-gpu 没 pip → `python -m ensurepip`；装包记得 `PIP_CACHE_DIR=/local/evan/cache/pip`。
4. und 路 frozen 且文本看不到噪声 → und 中间量 requires_grad=False，autograd 不建图，联合前向没有额外反传开销；**别**为了"优化"把 und 包进 no_grad 再 detach KV——训练期没必要，采样期才值得做 KV 缓存。
5. tiny 配置的 `mrope_section` 之和必须 = head_dim//2（tiny 是 [3,3,2]=8=16//2），改 head_dim 时记得同步。
6. checkpoint 只存可训练参数（frozen 塔由 pretrained_path 复原）——换 pretrained_path 会让旧 ckpt 失配，留意。
7. 机器上 sleep/凭证探测类命令可能被安全策略拦；长任务 nohup + log 轮询。

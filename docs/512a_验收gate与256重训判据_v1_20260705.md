# 512a 验收 gate 与「是否必须重训 stage256」判据 v1（2026-07-05）

> 背景：stage256（redesign, causal+MLF）在 297M 曝光后生成的全身 anime 构图出现头部截断。根因三因素（详见
> `当前进展_交接GPU.md` 2026-07-05 节 + 诊断产物 `data_analysis/outputs/headcrop_diag/`）：
> ①训练数据方图中心裁 × anime 62-66% portrait（顶损≥15% 占 37%）；②曝光收敛放大（193.5M 不显 / 297M 显）；
> ③NL-first 配方 vs 纯 tag eval 的 OOD 共因（NL 措辞重测：tag 版缺头 10/18 → NL 版 4/18，缓解但**不根治**——
> idx136 双 seed 在 NL 显式 "head to feet" 下仍无头 = 偏差已烘进权重）。
> 处置（Evan 拍板）：256 提前停于 304.1M（step132000）不重训；512a 上 multi-AR + per-domain 保头 anchor
> + square_only + native-affinity 域采样做数据侧纠正。**本文档回答：512a 训练中/后，怎样的 eval 结果算
> 「纠正成功」，怎样算「必须重训 256」，以及配套保障。**

## 1. 视觉 gate 协议（固定，不许中途改口径）

**Prompt 集（固定 13 条）**：anime evalset 全身构图 idx {000,018,044,052,062,064,127,133,136}（9 条）
+ 半身对照 idx {012,023,035,077}（4 条）。双口径：
- tag 版 = `experiments/eval/prompts/anime_evalset.jsonl` 原条目；
- NL 版 = `data_analysis/configs/anime_evalset_nl13_headcrop.jsonl`（全身条目显式含 "entire figure visible from head to feet"）。

**生成参数（与 256 基线两轮 eval 对齐，唯一放开项=分辨率）**：seeds 7/1007、steps 64、cfg 4.0、
`--weights ema`；512a ckpt 生成 **512×512**（native；与 256 基线的 256×256 相比，**缺头计数 B 率跨分辨率可比，
美学/CLIP 类指标不可直接比**——只用 B 率做 gate）。

**判读 rubric（与 2026-07-05 全量计数一致，逐张+顶部放大复核）**：A=头完整构图正常；B=想画全身/大半身但头被
上边缘截断；C=合理特写（头完整）；D=其它异常（注明，不计入 B 率）。B 率定义 = 9 全身 idx × 2 seeds 共 18 格中的 B 数。

**基线（256@297M ckpt, step129000, 全量复核值）**：tag 版 **10/18**，NL 版 **4/18**（其中 idx136 tag/NL 双口径
双 seed 全 B = 最顽固案例）。可选（建议做，一次性）：用同 rubric 补测 193.5M ckpt 的 tag 版 18 格，得到「涌现前」
基线锚点（此前 0/9 是宽松 rubric+单 seed 的数，不可直接混用）。

## 3. 「必须重训 stage256」判据（重大决策，须四条同时满足）

重训 256 ≈ 4+ GPU 天（6×8），触发前**必须同时**满足以下全部，缺一先走对应排查分支：

1. **纠正无效**：G2 后 tag 版 B 率仍 ≥7/18（相对 297M 基线 10/18 改善 <30%），且 G1→G2 无下降趋势；
2. **排除口径因素**：NL 版同样无改善（≥4/18）——若只有 tag 版差，说明是 tag-OOD 口径问题，修 eval/加 tag 曝光即可，不必重训；
3. **排除 512a 自身训坏**：同期非缺头指标健康（loss 正常收敛、DPG/美学抽测不倒退、无 mix/reresize 异常）——若 512a
   本身训坏了，先修 512a 再谈 256；
4. **失败模式确认**：人工确认失败样本仍是「构图截断」形态（躯干居中/头出上框），而非其它退化（画崩/语义错）。

**触发后的重训预案**（届时再拍，此处预埋选项）：256 重训必须带数据侧修正——候选 ①256 也上 multi-AR+anchor+affinity
（本轮 512a 代码全部 stage 无关、gated，直接可用；bucketdist 需换 elig_256 口径重测）②方图+top-bias anchor（最小改）
③加 SDXL 式 crop-conditioning（模型侧改动，本 pilot 未做，正式版 pipeline 应评估——见 §5）。

**反向判据（明确写死，防止过度反应）**：G1 达到「通过」档 ⇒ 缺头问题关闭，不再作为重训理由；G3 后 tag ≤1/18 ⇒
本修复路线（数据侧纠正优于重训）记为已验证结论，写回设计 doc。

## 4. G3 全套 eval 与对照（提前定口径，防止到时争议）

- 套件：anime evalset（tag 版 **+ NL 版并行双轨**，见 §5-2）3 seeds + DPG + fixedσ，
  参数与 rd256 各轮 eval 逐字一致（`--weights ema`），512×512 生成。
- 对照：**无 512 外部基线**（ab2fusion/ab1causal ckpt 已删、512 carry-forward 选项已放弃）→ 对照 = ①自身纵向
  （G1/G2/G3 曲线）②256@304M 基线横向（**分辨率混淆注明**：512 vs 256 生成，美学/tagger 分数天然不可直接比，
  只比相对趋势与 B 率）③Anima-2B（项目最终目标对照，512 可比）。
- tag-hit 指标注意：512a route 恢复 tag 10%（256 是零 tag）→ 预期 tag-hit 部分回补；若仍显著低于 ab2fusion@256
  的 0.518，先查口径（tag eval 对 NL-first 的结构性偏见）再下结论。

## 5. 配套保障（本轮已落地 or 待办；缺头问题之外必须保证的事）

1. **✅已落地（512a config/代码, 全 gated+单测 41 项+dryrun 6/6+smoke 12/12）**：multi-AR enabled、
   `crop_v_anchor {anime:0.15}`（方图裁/桶裁/re-resize 三路全走 anchor）、`square_only_domains [synthetic,textatlas]`
   （含退化路径硬不变量：S 域永不被裁进非方桶——2026-07-05 dryrun 抓漏后已修）、native-affinity 域采样
   （P(d|B)∝mix·P_native，全局 mix 期望精确不变）、warmup 曝光化、GC 三键（gen2=200/freeze=50/re-freeze=10000）。
2. **待办-eval 口径修正**：把 NL13 扩成**完整 NL 版 anime evalset（150 条全 NL 化）**，从 512a 起作为与 tag 版并行的
   双轨口径（190M 报告已建议过；不替换 tag 版，保历史可比）。负责：eval 线/下轮任务。
3. **待办-512b 语义同步**：`configs/stage512b_redesign_v1.yaml` 目前仍 multi_ar off + 无 anchor/affinity/square_only。
   **512a G1 通过后、512b 启动前必须同步整套缺头修复配置**（512b anime 0.78 是缺头风险最高的阶段），且
   native_bucket_dist 需按 512b 的 domain_mix 重算（P_native 表本身 stage 无关可复用，bucket_probs 派生值会变）。
4. **待办-1024 阶段**：同理预留；1024 的 elig/bucketdist 全部要重测（新口径）。
5. **运行监控阈值（v3 yaml 注释已写，此处存档；textatlas 口径 2026-07-05 深夜核验修正）**：`buf_reresize_anime>10%`
   或任一域 >20% ⇒ 查 config/bucketdist 漂移；`mix_anime` 偏离目标 >0.03 持续 2k 步 ⇒ 查 fetch_workers/缓存；
   `synthetic` reresize>0 ⇒ 代码回归（native 100% 方 ⇒ 兜底数学上不可触发 = 真硬不变量）；`textatlas` reresize
   **稳态 ≈9% 是设计预期，不是异常**——守恒律推导：native 非方占比 9.03%（config 实测表 1-0.9097），square_only 下
   这些记录只能经域内兜底裁**进方桶**消费（= 旧方图管线对 100% textatlas 的同款处理，非破坏性），长期消费率必然
   ≡ 非方流入率 ≈9%；2×8 开桶相实测累计 9.7% 吻合，且 step50-250 全程为 0（buffer 死重累积期）step300 才跳到 9.7%
   ——**早期 0 是假象，勿据此把 =0 当基线**。>20% 或持续爬升才 ⇒ 查供给/config。
   注意两点：①「S 域永不进非方桶」硬不变量由代码路径+dryrun 断言保证，**不能**用 buf_reresize 计数判（计数含良性入方桶兜底）；
   ②stage512a yaml L118 注释「synthetic/textatlas 配 square_only 后应≈0」对 textatlas 不准确，但 config 被在跑 job
   实时读（坑#11）不能改，待 512a 训完后顺手修正。
6. **crop-conditioning 备忘**：SDXL 用裁剪坐标条件化中和裁剪偏置（推理置 0）。本 pilot 不做（模型侧改动）；
   若做正式版 pipeline / 触发 256 重训，应重新评估（它能让「裁过的数据」也变成干净信号，比纯 bucketing 更彻底）。
7. **谱系记录**：512a init_from = `redesign_512a_prep/init_from_512a_step132000.pt`（256@304.1M，提前停训点）；
   256 的 384M 设计目标未跑满是缺头止损决策（非事故），对比实验引用 256 数据时注明 304M。
